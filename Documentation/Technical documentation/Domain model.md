# Доменная модель

## Объекты мониторинга

`MonitoredObject` содержит общее состояние сервера и контейнера:

- неизменяемый `Guid`;
- URL endpoint и описание;
- признак включённого мониторинга;
- последнее полученное имя;
- текущий `MonitoringStatus`;
- число последовательных ошибок;
- время последней и последней успешной проверки;
- идентификатор текущего инцидента, необходимый для идемпотентной доставки уведомлений;
- явную монотонную `Version`, которая меняется при административной настройке и записи результата проверки.
- отдельные принятые `ConfigRevision` и `CheckGeneration`, которые не изменяются результатами endpoint-проверок.

`MonitoredServer` дополнительно хранит обязательное задаваемое администратором `Name` и добавляет операцию успешной проверки сервера. Полученное от endpoint внутреннее имя остаётся в общем `LastKnownName` и не заменяет административное имя. `MonitoredContainer` хранит необязательный `Guid? ServerId` и последнее время запуска `StartedAtUtc`. Контейнер связан с нулём или одним сервером; `Guid.Empty` запрещён. `AssignServer` меняет связь и увеличивает `Version`, сохраняя результат мониторинга и инцидент. `MonitoredServer.RecordContainerLinksChanged` увеличивает версию сервера при изменении связей, чтобы stale-редактор не перезаписывал актуальный набор.

## Создание и изменение

Объекты создаются только с непустым идентификатором и абсолютным HTTP/HTTPS URL с непустым host. Имя сервера обязательно и нормализуется обрезкой пробелов. Описание нормализуется, пустая строка превращается в `null`. Длины URL, описания, имени сервера и полученного внутреннего имени ограничены `ModelConstraints`.

Публичных сеттеров для значимого состояния нет. Настройки меняются через `UpdateSettings` или `SetMonitoringEnabled`, результаты проверок — через специализированные методы.

Каждая фактическая доменная мутация увеличивает `Version`. Infrastructure использует исходное значение как optimistic concurrency token, поэтому stale monitoring/admin write не может перезаписать более новое состояние.

Смена endpoint очищает внутреннее имя и времена, полученные от предыдущего адреса, а также сбрасывает статус и инцидент. Административное имя сервера при этом сохраняется. Для контейнера дополнительно очищается `StartedAtUtc`.

## Переходы мониторинга

Начальное состояние — `Unknown`.

- Успех из `Unknown` даёт `BecameAvailable` и состояние `Available`.
- Ошибка увеличивает `ConsecutiveFailures`.
- Достижение порога ошибок переводит объект в `Unavailable` и даёт `BecameUnavailable`.
- Успех из `Unavailable` даёт `Recovered`.
- Отключение мониторинга даёт `MonitoringDisabled`, возвращает `Unknown`, сбрасывает ошибки и очищает идентификатор текущего инцидента без recovery.

Повторная ошибка уже недоступного объекта не создаёт новый переход. Успех всегда сбрасывает счётчик ошибок.

## Время

Доменные методы принимают `DateTimeOffset` только с нулевым смещением. Время запуска контейнера не может быть позже времени проверки.

## Уведомления и доступ

`TelegramChat` хранит внутренний идентификатор, Telegram chat ID и отображаемое имя. `NotificationBinding` через фабрики создаёт связь ровно с сервером или контейнером. Для текущего инцидента каждая привязка отдельно хранит идентификаторы успешной outage- и recovery-доставки. Это позволяет повторять только неуспешные доставки и не подменять частичный результат глобальным флагом объекта.

`ServerVisibilityPermission` и `ContainerVisibilityPermission` остаются только типами совместимости прежних use case до этапа 05. Они исключены из целевой EF-модели; создавать ресурсные назначения больше нельзя. Контейнеры с родителем и без него доступны администраторам без отдельных назначений.

## Общая модель сетки

`Cluster` содержит идентичность/позиции, `SharedAccount` с единственной Administrator и защищёнными реквизитами, Pending/decisions/controls/conflicts/tombstones, observer streams, incidents и delivery ledger. Login нормализуется FormKC/Trim/uppercase. Self-disable/self-delete и удаление последнего активного администратора проверяются чистым методом по переданному принятому count; упорядоченная проверка нескольких аккаунтов принадлежит будущему reducer.

Состояние общего аккаунта, ConfigRevision, оперативные наблюдения и cursor разделены. Хранимые сводки ссылаются на исходные events/intents, recovery entitlement не зависит от существования binding. `HistoryRetention` защищает незавершённую работу и compact safety markers независимо от возраста. Подробная карта сущностей и реализованных границ — [Shared cluster storage.md](Shared%20cluster%20storage.md). Workers/общий вход/replay этой моделью ещё не включены.

## Покрытие тестами

Тесты проверяют основные переходы, обязательность и нормализацию имени сервера, сброс ошибок, отключение мониторинга, очистку endpoint-specific состояния, UTC и допустимость notification binding.
