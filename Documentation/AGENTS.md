# Documentation

## Назначение

Каталог содержит документы трёх уровней:

- `Technical requirements.md` — краткие бизнес-требования без деталей реализации и примеров кода;
- `Technical` — фактическое техническое устройство проекта;
- `Plans` — последовательность активных работ и исторический результат завершённых этапов.

## Правила актуализации

- Не дублировать технические детали в бизнес-требованиях.
- Изменение поведения системы отражать в бизнес-требованиях только тогда, когда меняется пользовательский или эксплуатационный результат.
- Изменение архитектуры, контрактов, конфигурации или процессов разработки отражать в соответствующем файле `Technical`.
- При изменении реализованности активного этапа обновлять его раздел `Статус` и общий активный план.
- План со статусом `Завершён` не редактировать вслед за последующими изменениями проекта: это зафиксированная история выполненного этапа.
- Новую работу после завершения плана описывать в новом плане, а текущее устройство проекта — в `Technical`.
- При добавлении нового класса технических решений создавать отдельный тематический Markdown-файл, а не разрастать несвязанный документ.
- При содержательном изменении файлов в этом каталоге проверять актуальность данного `AGENTS.md`.
