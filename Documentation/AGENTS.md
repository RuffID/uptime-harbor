# Documentation

## Назначение

Каталог содержит документы трёх уровней:

- `Business logic` — пользовательские правила и бизнес-требования; основной документ — `Business requirements.md`;
- `Technical documentation` — фактическое техническое устройство проекта;
- `Plans` — последовательность активных работ и исторический результат завершённых этапов.
- `README.md` — общая навигация; `Business logic/README.md`, `Technical documentation/README.md` и `Plans/README.md` — тематические оглавления. Исторические отчёты `V1 ... Review ...` находятся в `Technical documentation`.

## Правила актуализации

- Не дублировать технические детали в бизнес-требованиях.
- Изменение поведения системы отражать в бизнес-требованиях только тогда, когда меняется пользовательский или эксплуатационный результат.
- Изменение архитектуры, контрактов, конфигурации или процессов разработки отражать в соответствующем файле `Technical documentation`.
- При изменении реализованности активного этапа обновлять его раздел `Статус` и общий активный план.
- План со статусом `Завершён` не редактировать вслед за последующими изменениями проекта: это зафиксированная история выполненного этапа.
- Новую работу после завершения плана описывать в новом плане, а текущее устройство проекта — в `Technical documentation`.
- При добавлении нового класса технических решений создавать отдельный тематический Markdown-файл, а не разрастать несвязанный документ.
- При содержательном изменении файлов в этом каталоге проверять актуальность данного `AGENTS.md`.
- Новые планы оформлять по `Plans/README.md`: `main.md`, обязательный `open-questions.md`, этапы и согласованные статусы. Завершённые планы не переделывать под новый шаблон и не актуализировать вслед за кодом.
- В составном плане `Plans/multi-node-sync-and-permissions-2026-10-18-(not-started)` этапы находятся в отдельных папках с `main.md` и документами подэтапов; статус подэтапа синхронизировать в его файле, обзоре этапа и общем плане. Требования и открытые вопросы остаются общими в корне плана.
- Каждый новый документ добавлять в оглавление и соответствующую solution folder; общий каталог хранить только в корне решения.
