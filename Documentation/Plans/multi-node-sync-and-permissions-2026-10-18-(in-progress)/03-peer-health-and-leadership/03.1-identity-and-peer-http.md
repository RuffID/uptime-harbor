# Подэтап 03.1. Настройки, идентичность и защищённый peer HTTP

Статус: completed

## Цель и результат

Узел имеет валидируемую конфигурацию и отдельный доверенный peer transport.

## Зависимости и границы

Зависимости: [02](../02-domain-and-persistence/main.md).

Родительский [этап 03](main.md) задаёт общие ограничения и критерии. [Общий план](../main.md) содержит сводные статусы; [требования](../business-requirements.md) и [техническое проектирование](../technical-design.md) определяют согласованное поведение. Подготовка документа не разрешает реализацию, запуск приложения, внешние проверки или включение функции.

## Затрагиваемые части проекта

Будущие peer/cluster модули в Application и Infrastructure, durable storage в `Infrastructure/Persistence`, `Infrastructure/Monitoring`, `Infrastructure/Telegram`, `Web/Configuration`, `Web/Controllers`, `Web/Program.cs`; конфигурационные примеры без секретов, соответствующие тесты и локальные `AGENTS.md`.

Работа ограничена перечисленными ниже сценариями; смежные компоненты изменяются только при необходимости выполнить результат подэтапа.

## Работы

- [x] Создать отдельные защищённые peer endpoints и HTTPS adapter для интернет-связи без обязательного VPN. Проверять действительные сертификаты доменных имён; учесть выпуск/обновление сертификатов и TLS на Nginx с изолированным внутренним HTTP. Валидировать отправителя, ClusterId, версию, payload, replay и timeout; не смешивать их с публичным анонимным контрактом проверяемых приложений.
- [x] Ввести типизированные настройки: enable/mode, адреса/идентичность peers, heartbeat, timeout, 30-секундное окно, минутный интервал настроек и пределы передачи. Секреты не попадут в ответы или логи.

- [x] Актуализировать затронутые локальные `AGENTS.md` и фактическую техническую документацию в пределах реализованного изменения; новые документы включить в навигацию и solution.

## Проверки

Fake HTTP: неверные NodeId/ClusterId, аутентификация, replay, несовместимая версия, timeout и oversized body; проверить отсутствие секретов в ответах/логах.

Общие сценарии [родительского этапа](main.md#проверки) сохраняются. Минимальные изолированные проверки подтверждают production policy, storage и adapter API в указанном ниже объёме; выборы DotNext и crash recovery ими не объявляются проверенными. Реальные БД, peer HTTP, процессы, браузер и Telegram учитываются отдельно в [этапе 10](../10-verification-and-acceptance/main.md).

Команды из плана не являются разрешением их запускать. Непроведённая обязательная проверка остаётся открытой; готовность кода при ожидающей приёмке обозначается `verification`.

## Результат выполнения

2026-10-29: Добавлены ClusterOptions с fail-fast validation, отдельный Kestrel/mTLS peer listener, proxy boundary, certificate pin/SAN/CA, envelope identity/generation/version/challenge, native NodeId binding, durable nonce inbox и лимиты. Browser cookies не авторизуют peer. Изолированно проверены envelope, сертификаты, replay/reopen, fake peer responses/timeout, конфигурация и разделение listeners. Настоящие HTTPS/Nginx/CRL/renewal не запускались.

Сборки и общий минимальный набор этапа — [Testing.md](../../../Technical%20documentation/Testing.md#проверка-этапа-03). Будущие accepted recovery/account/trust/authority порты по умолчанию закрыты; соседние этапы не реализованы и функция не включена.
