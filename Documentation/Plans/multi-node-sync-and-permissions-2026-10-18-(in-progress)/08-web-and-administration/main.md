# Этап 08. Интерфейс и управление с любого узла

Статус: completed

## Цель

Показать действующее состояние, Pending и конфликты; обеспечить всем активным администраторам одинаковое управление объектами, пользователями и сеткой через любой узел.

## Зависимости и границы

После [05](../05-permissions-and-ownership/main.md) и [07](../07-leader-notifications/main.md). Интерфейс не превращает Pending в немедленно действующую конфигурацию. Новый клиентский код — TypeScript по профильным скиллам проекта; AJAX-поток без перезагрузки страницы.

## Затрагиваемые части проекта

`Web/Pages/Index`, `Pages/Admin`, `Controllers`, `Controllers/Models`, `Hubs`, `Http/JsonResultMapper`, `wwwroot/ts/pages`, shared/types; Application DTO/read queries, Dashboard и administration services. Web tests и `tests/Frontend`; локальные `AGENTS.md`, фактические документы `Web application.md`, `Authentication and visibility.md`.

## Границы ответственности подэтапов

Подэтапы используют единую проверку активного администратора 05 и command pipeline 04. API/DTO проверяются изолированно, browser acceptance отдельно — 10.4. Ресурсных матриц и форм выдачи доступа нет.

## Проверки

Изолированно: сериализация реальными MVC options, авторизация активного администратора до side effects, отсутствие секретов, Pending/conflict/rejected/reconnect, общий аккаунт, global delete, test-send с ведомого. Frontend-тесты с заглушками без сети/браузера.

Отдельно в браузере: один аккаунт входит на двух узлах, два администратора видят все объекты, создание/изменение общих пользователей, отключение с открытой сессией, offline edit, конфликт, перенос контейнера и mobile layout.

## Критерии приёмки

- [x] Пользователь понимает, сохранена заявка или уже изменена действующая конфигурация.
- [x] Редактор позволяет исправить/отменить непринятую заявку с подтверждением результата; уже принятое изменение исправляется новой правкой, конфликт не откатывает первую принятую настройку.
- [x] Каждый активный администратор одинаково управляет всеми объектами, чатами, observers и пользователями.
- [x] Пользователи общие, роли не выбираются; один login не создаёт разные активные записи на узлах.
- [x] Защищённые данные пароля и токены отсутствуют в UI/DTO/SignalR/ошибках.
- [x] Конфликт и недоступность главного обрабатываются без потери ввода и ложного сообщения об общем успехе.
- [x] Видны частичная доступность и проблемные направления без объявления цели полностью упавшей и без ложного сообщения о смене главного.
- [x] Глобальное удаление и защита последнего активного администратора представлены понятно; локального скрытого удаления нет.

- [x] UI/API одинаково проверяют активного администратора; диагностика всей сетки доступна каждому, metadata показаны по observers.
