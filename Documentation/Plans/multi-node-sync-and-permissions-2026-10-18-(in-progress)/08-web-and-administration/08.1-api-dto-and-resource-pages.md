# Подэтап 08.1. API, DTO и страницы администратора

Статус: not-started

## Цель и результат

Страницы и API дают полный доступ активному администратору и защищают секретные поля.

## Зависимости и границы

Зависимости: [05](../05-permissions-and-ownership/main.md), [07](../07-leader-notifications/main.md).

Родительский [этап 08](main.md), [общий план](../main.md), [требования](../business-requirements.md) и [техническое проектирование](../technical-design.md) задают границы. Подготовка документа не разрешает реализацию, запуск приложения или внешние проверки.

## Затрагиваемые части проекта

Razor Pages, controllers, DTO, SignalR, frontend-модули и страницы объектов/чатов/пользователей. Профильные тесты, ближайшие `AGENTS.md` и актуальная техническая документация обновляются при будущей реализации.

## Работы

- [ ] Применить единую проверку активного администратора к чтению и изменениям всех объектов, пользователей и диагностики; ресурсные фильтры и формы назначения доступа исключить.
- [ ] Контейнеры и серверы показывать всем администраторам; перенос, отвязка и выбор observers не требуют дополнительных разрешений.
- [ ] Не передавать PasswordHash, security stamp, пароли и токены в обычные DTO/DOM/SignalR/ошибки. Использовать существующие ServiceResult/JsonResultMapper, antiforgery и безопасные model-state errors.
- [ ] Выбор observers сохранять обычной заявкой; результаты и различающиеся endpoint-данные показывать по узлам без вымышленного общего значения.
- [ ] Актуализировать затронутые локальные `AGENTS.md` и фактическую техническую документацию; новые документы включить в навигацию и solution.

## Проверки

Изолированно проверить реальные MVC options, antiforgery, model-state errors, direct API активным/анонимным/отключённым аккаунтом, полный список сущностей для двух администраторов и отсутствие секретов в DTO/DOM.

Изолированные проверки не подменяют SQL Server, peer HTTP, браузер и Telegram. Внешняя приёмка учитывается отдельно в [этапе 10](../10-verification-and-acceptance/main.md); команды из плана не разрешены автоматически.

## Критерии приёмки

- [ ] Каждый активный администратор видит и изменяет все объекты через UI/API.
- [ ] Серверная авторизация обязательна; хеши и секреты не раскрываются, таблицы отдельных разрешений отсутствуют.
- [ ] Работы и применимые проверки выполнены; непроведённая внешняя приёмка остаётся открытой.
- [ ] Статус согласован с родительским этапом и общим планом.
