# Подэтап 04.1. Ожидающие заявки и результаты

Статус: not-started

## Цель и результат

На любом узле сохраняется durable заявка и отслеживается её окончательный результат.

## Зависимости и границы

Зависимости: [03](../03-peer-health-and-leadership/main.md), [05.1](../05-permissions-and-ownership/05.1-subjects-and-resource-policies.md).

Родительский [этап 04](main.md) задаёт общие ограничения и критерии. [Общий план](../main.md) содержит сводные статусы; [требования](../business-requirements.md) и [техническое проектирование](../technical-design.md) определяют согласованное поведение. Подготовка документа не разрешает реализацию, запуск приложения, внешние проверки или включение функции.

## Затрагиваемые части проекта

Новые сценарии синхронизации в Application, сценарные UoW, journal/cursor/conflict/tombstone storage в Infrastructure, peer contracts и workers, настройки. Текущие `ObjectAdministrationService` и `NotificationAdministrationService` будут подключаться к этим сценариям в следующих этапах.

Работа ограничена перечисленными ниже сценариями; смежные компоненты изменяются только при необходимости выполнить результат подэтапа.

## Работы

- [ ] Сохранить OperationId, origin NodeId, actor UserId, target, base revision и безопасный payload одной локальной транзакцией. Проверять принятого активного администратора; непринятые аккаунты/пароли не дают доступа.
- [ ] Разрешить исправление и отмену непринятой заявки: при подтверждённой замене применяется только последнее значение, при отмене сохраняется действующая настройка. Долговременно хранить результат и исключать принятие старого варианта после retry/restart.
- [ ] Обрабатывать гонку с принятием: если команда уже принята, вернуть этот результат без обещания отмены; возврат или исправление — новая авторизованная команда. При недоступности подтверждения действие не показывается завершённым.
- [ ] Логировать подачу, замену, отмену и отказ по контракту 01.3 с достоверным actor и OperationId; сообщения на английском, без payload/секретов, без повторного успеха при retry или успеха после отката.
- [ ] Назначать общую ревизию только принятой записи; переносить результаты Pending/Committed/Conflict/Rejected обратно на исходный узел.

- [ ] Для старой восстановленной копии приостановить автоматическую передачу Pending. Сверить OperationId и принятые/отменённые/заменённые результаты; только оставшиеся непринятые заявки показать для подтверждения пользователем с повторной проверкой активного администратора и base revision. Не распространять это требование на обычный рестарт актуального узла.

- [ ] Актуализировать затронутые локальные `AGENTS.md` и фактическую техническую документацию в пределах реализованного изменения; новые документы включить в навигацию и solution.

## Проверки

Проверить restore старого backup с уже принятой, отменённой, заменённой и действительно непринятой заявками; без подтверждения не передавать последнюю, после подтверждения отклонять отключённый аккаунт/устаревшую base revision.

Проверить offline save/restart, замену А → Б на А → В без применения Б, отмену до принятия, гонку замены/отмены с принятием, потерянный ответ, поздний повтор старой заявки и восстановление результата после рестарта; локальная заявка не меняет accepted configuration. Проверить достоверность логирования успеха/отказа/отмены без дублей и секретов.

Общие сценарии [родительского этапа](main.md#проверки) сохраняются. Изолированные проверки подтверждают алгоритм; реальные БД, peer HTTP, процессы, браузер и Telegram учитываются отдельно в [этапе 10](../10-verification-and-acceptance/main.md).

Команды из плана не являются разрешением их запускать. Непроведённая обязательная проверка остаётся открытой; готовность кода при ожидающей приёмке обозначается `verification`.

## Критерии приёмки

- [ ] Непринятый аккаунт/пароль не используется для входа; заявка и результат переживают restart.
- [ ] Подтверждённо отменённый или заменённый вариант не применяется; принятое изменение не откатывается отменой; результат переживает потерянный ответ и рестарт.
- [ ] Старый backup не применяет устаревшие заявки автоматически и не повторяет уже принятую, отменённую или заменённую операцию.
- [ ] Работы и применимые проверки подэтапа выполнены, результат и ограничения зафиксированы.
- [ ] Статус согласован с таблицами родительского этапа и общего плана; незавершённая внешняя приёмка не объявлена выполненной.
