# Подэтап 02.3. Миграции схемы

Статус: not-started

## Цель и результат

Подготовлены новые миграции совместимой схемы без запуска backfill.

## Зависимости и границы

Зависимости: [02.2](02.2-durable-storage-and-uow.md).

Родительский [этап 02](main.md) задаёт общие ограничения и критерии. [Общий план](../main.md) содержит сводные статусы; [требования](../business-requirements.md) и [техническое проектирование](../technical-design.md) определяют согласованное поведение. Подготовка документа не разрешает реализацию, запуск приложения, внешние проверки или включение функции.

## Затрагиваемые части проекта

`UptimeHarbor.Domain/Monitoring`, `Domain/Access`, `Domain/Notifications`; `Application/Abstractions/Persistence`, `Application/Abstractions/UnitOfWork`; `Infrastructure/Persistence`, его `Configurations`, `UnitOfWork`, `Repositories`, новые миграции. Соответствующие Domain/Application/Infrastructure tests, ближайшие `AGENTS.md`; актуальные документы `Domain model.md`, `Persistence.md`, `Database migrations.md`.

Работа ограничена перечисленными ниже сценариями; смежные компоненты изменяются только при необходимости выполнить результат подэтапа.

## Работы

- [ ] Подготовить миграцию без автоматического назначения всем администраторам доступа и без выдуманного автора исторических сущностей. Данные для backfill отделить от создания схемы.

- [ ] Актуализировать затронутые локальные `AGENTS.md` и фактическую техническую документацию в пределах реализованного изменения; новые документы включить в навигацию и solution.

## Проверки

Проверить исходники migrations и snapshot, отсутствие переписывания baseline и автоматической выдачи прав; применение к SQL Server вынести в 10.2/10.6.

Общие сценарии [родительского этапа](main.md#проверки) сохраняются. Изолированные проверки подтверждают алгоритм; реальные БД, peer HTTP, процессы, браузер и Telegram учитываются отдельно в [этапе 10](../10-verification-and-acceptance/main.md).

Команды из плана не являются разрешением их запускать. Непроведённая обязательная проверка остаётся открытой; готовность кода при ожидающей приёмке обозначается `verification`.

## Критерии приёмки

- [ ] Схема отделена от сопоставления старых данных; неизвестные владельцы не выдуманы, факт применения миграции не заявлен без внешней проверки.
- [ ] Работы и применимые проверки подэтапа выполнены, результат и ограничения зафиксированы.
- [ ] Статус согласован с таблицами родительского этапа и общего плана; незавершённая внешняя приёмка не объявлена выполненной.
