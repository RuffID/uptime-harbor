# Этап 08. Интерфейс и управление с любого узла

Статус: not-started

## Цель

Показать пользователю действующее состояние, ожидающие изменения и конфликты; обеспечить управление сущностями и доступом через любой узел без обхода серверных прав.

## Зависимости и границы

После [05](05-permissions-and-ownership.md) и [07](07-leader-notifications.md). Интерфейс не превращает Pending в немедленно действующую конфигурацию. Новый клиентский код — TypeScript по профильным скиллам проекта; AJAX-поток без перезагрузки страницы.

## Затрагиваемые части проекта

`Web/Pages/Index`, `Pages/Admin`, `Controllers`, `Controllers/Models`, `Hubs`, `Http/JsonResultMapper`, `wwwroot/ts/pages`, shared/types; Application DTO/read queries, Dashboard и administration services. Web tests и `tests/Frontend`; локальные `AGENTS.md`, фактические документы `Web application.md`, `Authentication and visibility.md`.

## Работы

- [ ] Адаптировать имеющиеся страницы объектов/чатов/пользователей под ресурсные права, а не только роль Administrator. Системное управление локальными учётными записями оставить локальной административной функцией.
- [ ] Показать текущий узел, главного, наличие большинства, время последней связи и отставание в понятной форме. Закрытые сущности и технические секреты не раскрывать через диагностику.
- [ ] Показать «Доступен не со всех узлов», разрешённые пользователю результаты по наблюдателям и неполное покрытие. Проблемный из-за БД узел отличать от обычного follower и от исправного узла без peer-связи. Не раскрывать скрытые узлы/цели через диагностические подробности.
- [ ] В редакторе отделить действующую конфигурацию от сохранённой заявки. Показывать «Ожидает синхронизации», принятие, отказ и конфликт; при offline не обещать немедленного применения.
- [ ] Сделать выбор пользователя по узлу и имени с однозначным ID; дать владельцу назначать доступ с любого узла. Не создавать удалённую Identity-учётку и не переносить пароль.
- [ ] Показать применимые разрешения и владельцев. Собственные права нельзя снять; объяснять причину отказа. Последний владелец защищён также серверной проверкой.
- [ ] Для чатов отдельно показывать видимость, изменение с удалением, управление привязками и доступом. Фильтровать список целей и скрытые bindings на сервере.
- [ ] Отображать контейнер независимо от видимости сервера; скрытые имя, описание, ID-связь и прочие данные родителя не попадут в DTO/DOM/подсказки.
- [ ] Добавить разбор конфликтов: понятные варианты, действующая версия, выбор результата и состояние его согласования. Запретить доступ к чужим скрытым конфликтным payload.
- [ ] Подтверждать глобальное удаление с объяснением последствий и зависимостей. Кнопки «скрыть только у себя» и отдельного права удаления нет; Pending deletion не выдавать за завершённое на всех узлах.
- [ ] При отзыве прав и синхронизации обновлять списки/карточки/SignalR-получателей, обрабатывать отказы открытого редактора. Reconnect перечитывает принятую конфигурацию и состояние заявок.
- [ ] Сохранить принятые `ServiceResult`/`JsonResultMapper`, antiforgery, безопасные model-state errors и серверную валидацию. UI-права не заменяют проверку use case.
- [ ] Обновить локальные `AGENTS.md` и фактические Web-документы; новые документы подключать только как solution items.

## Проверки

Изолированно: сериализация DTO реальными MVC options, resource authorization до side effects, отсутствие скрытых parent/chat/target fields, pending/conflict/rejected/reconnect flow, self-revoke, global delete, test-send с ведомого. Frontend — тесты с заглушками без реального fetch или браузера.

Отдельно в браузере: две разные учётные записи и узлы, администратор без прав, edit с потерянной связью, изменение прав во время открытой карточки, согласование конфликта, контейнер без видимого сервера, мобильный layout. Browser acceptance не заменяется статическим чтением TypeScript.

## Критерии приёмки

- [ ] Пользователь понимает, сохранена заявка или уже изменена действующая конфигурация.
- [ ] Одноимённые пользователи разных узлов различимы при выдаче прав.
- [ ] Роль администратора не раскрывает скрытые сущности ни UI, ни прямым запросом.
- [ ] Конфликт и недоступность главного обрабатываются без потери ввода и ложного сообщения об общем успехе.
- [ ] Видны частичная доступность и проблемные направления без объявления цели полностью упавшей и без ложного сообщения о смене главного.
- [ ] Удаление и отказ от собственных прав представлены согласно требованиям; нет скрытого локального удаления.
