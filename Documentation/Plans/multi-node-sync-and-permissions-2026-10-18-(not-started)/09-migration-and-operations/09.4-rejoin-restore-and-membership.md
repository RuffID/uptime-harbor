## Работы

- [ ] Описать join/rejoin, безопасное изменение состава, удаление узла без удаления общих пользователей, восстановление БД, compaction и замену адреса/секрета.
- [ ] Для старого узла/backup до запуска рабочих процессов сверить ClusterId/NodeId, durable term/log и курсор с принятой историей. При возможности догрузить журнал, иначе восстановить только общую проекцию из актуального snapshot. Старую outbox не запускать до сверки доставки; исключить клон NodeId и воскрешение удалений.

- [ ] Управление составом/доверием доступно любому активному администратору. Проверять аккаунт и majority до изменения данных; отдельное операторское назначение не требуется.

- [ ] При восстановлении старого backup удерживать Pending до сверки OperationId с принятой историей и результатами отмены/замены. Оставшиеся непринятые заявки требуют подтверждения пользователем, активного администратора и base revision; автоматической повторной подачи нет.

- [ ] Актуализировать затронутые локальные `AGENTS.md` и фактическую техническую документацию в пределах реализованного изменения; новые документы включить в навигацию и solution.

## Проверки

Проверить restore старого backup с принятыми/отменёнными/заменёнными и непринятыми заявками: сначала сверка, затем подтверждение оставшихся пользователем; без него передачи нет.

Проверить старые term/log/cursor, compaction, потерянную БД, clone NodeId, замену адреса/секрета и исключение узла без удаления аккаунтов. Активный администратор управляет составом, анонимный/отключённый получает отказ; majority сохраняется.

Общие сценарии [родительского этапа](main.md#проверки) сохраняются. Изолированные проверки подтверждают алгоритм; реальные БД, peer HTTP, процессы, браузер и Telegram учитываются отдельно в [этапе 10](../10-verification-and-acceptance/main.md).

Команды из плана не являются разрешением их запускать. Непроведённая обязательная проверка остаётся открытой; готовность кода при ожидающей приёмке обозначается `verification`.

## Критерии приёмки

- [ ] Старая outbox закрыта до сверки, удаления не воскресают, состав не уменьшается автоматически.
- [ ] Состав/доверие меняются активным администратором; уход узла не удаляет пользователей, принятую историю и роль.
- [ ] Restore не воспроизводит принятые/отменённые/заменённые команды; остальные непринятые заявки ожидают подтверждения пользователя.
- [ ] Работы и применимые проверки подэтапа выполнены, результат и ограничения зафиксированы.
- [ ] Статус согласован с таблицами родительского этапа и общего плана; незавершённая внешняя приёмка не объявлена выполненной.
