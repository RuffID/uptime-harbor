# Этап 09. Первый запуск и эксплуатация

Статус: not-started

## Цель

Подготовить первый запуск общих пользователей и единственной роли, восстановление узлов и диагностику без потери принятых аккаунтов, настроек и событий.

## Зависимости и границы

После этапов 02–08. Основной путь — новая сетка из одного узла и присоединение пустых узлов; будущий rejoin старого узла/backup остаётся отдельной процедурой. Развёрнутой v1 нет: импорт, backfill и переключение старых workers исключены. Подготовка runbook и migrations не разрешает подключение к БД, запуск хоста, backup-команд или deployment.

## Затрагиваемые части проекта

EF migrations схемы первого выпуска, `Infrastructure/Identity`, `Infrastructure/InfrastructureInitializationExtensions.cs`, `Services/DataBase/DataBaseCheckUpService.cs`, `BackupService.cs`, `Web/Configuration`, конфигурационные примеры; документация `Database migrations.md`, `Deployment.md`, `Configuration.md`, `Testing.md` и соответствующие `AGENTS.md`.

## Границы ответственности подэтапов

09 собирает процедуры из готовых механизмов: bootstrap/membership — 03, snapshot/replay — 04, схема — 02.3. Повторные реализации не создаются. 09.2/09.3 отменены как неприменимые; активные зависимости не требуют их выполнения.

## Проверки

Изолированно: одноузловой bootstrap с одним администратором, пустой join с получением аккаунтов/роли/защищённых данных пароля, отказ merge несвязанных данных, snapshot/replay без переноса сессий и секретов узла, clone NodeId, rejoin после compaction, подтверждение Pending из backup.

Отдельная разрешаемая приёмка: создание новой схемы и backup/restore копий SQL Server новой модели, bootstrap одного и трёх настоящих узлов, доступы бота к тестовым чатам, TLS/reverse proxy, rejoin отставшего узла, rollback будущего обновления. Команды из runbook не выполнять автоматически.

## Критерии приёмки

- [ ] Пустой join получает все общие данные, пользователей и единственную роль; отдельные локальные аккаунты не создаются.
- [ ] Первый узел создаёт общего администратора и сетку с большинством 1; несвязанный непустой join отклоняется без импорта.
- [ ] Старая копия не начинает проверки/отправку до сверки истории и не воскрешает принятые удаления.
- [ ] Readiness и sender gate открываются после готовности новой модели; независимого sender в обход главного нет.
- [ ] Backup/restore, совместимость и восстановление проверены отдельно либо этап остаётся `verification`.
- [ ] Отказ/изъятие узла сохраняет общих пользователей и принятую историю; аварийного автоматического уменьшения состава нет.
- [ ] Эксплуатационные инструкции содержат точный порядок, условия остановки и границы разрешений.

- [ ] Составом и доверием управляет активный администратор через безопасную согласованную процедуру.
