# Этап 09. Переход существующих установок и эксплуатация

Статус: not-started

## Цель

Подготовить безопасный ввод сетки с новыми ACL и ревизиями, восстановление узлов и эксплуатационную диагностику без потери владельцев и принятых событий.

## Зависимости и границы

После этапов 02–08. Основной путь — bootstrap и присоединение узлов с пустыми общими данными. Дополнительно предусмотреть отдельный импорт непустой установки и rejoin старого узла/backup. Подготовка runbook и файлов миграции не разрешает подключение к действующей БД, запуск хоста, backup-команд или deployment.

## Затрагиваемые части проекта

Новые EF migrations и контролируемый backfill, `Infrastructure/Identity`, `Infrastructure/InfrastructureInitializationExtensions.cs`, `Services/DataBase/DataBaseCheckUpService.cs`, `BackupService.cs`, `Web/Configuration`, конфигурационные примеры; документация `Database migrations.md`, `Deployment.md`, `Configuration.md`, `Testing.md` и соответствующие `AGENTS.md`.

## Границы ответственности подэтапов

09 собирает процедуры из готовых механизмов: bootstrap/membership — 03, snapshot/replay — 04, схема — 02.3. Здесь не создаются вторые реализации. 09.1 и 09.4 не требуют импорта непустых данных; 09.2/09.3 проверяются на искусственных данных без угадывания действующей карты владельцев.

## Проверки

Изолированно на искусственных данных: bootstrap пустой сетки, join пустого узла со своим Identity, snapshot/replay без переноса паролей, отдельный разбор непустого импорта, маппинг дубликатов, отсутствие owner map, отсутствие владельца после каскада, идемпотентность backfill, старый/недопустимый clone NodeId, rejoin с журналом и после compaction, валидация конфигурации без секретов. Это не проверка production-данных.

Отдельная разрешаемая приёмка: backup/restore и миграция копий SQL Server, bootstrap трёх настоящих узлов, остановка старых workers, доступы бота к тестовым чатам, TLS/reverse proxy, rejoin отставшего узла, rollback в выбранной точке. Команды из runbook не выполнять автоматически.

## Критерии приёмки

- [ ] Основной пустой join получает общие данные и ACL синхронизацией; локальный администратор нового узла не получает автоматических прав на чужие сущности.
- [ ] Для непустого импорта есть предварительный разбор и явная карта начальных владельцев; неизвестные значения не заменены догадками. Отсутствие реальных установок для импорта не блокирует реализацию и проверку основного пустого пути.
- [ ] Старая копия не начинает проверки/отправку до сверки истории и не воскрешает принятые удаления.
- [ ] Переключение не запускает одновременно старых и новых независимых отправителей.
- [ ] Backup/restore, совместимость и восстановление проверены отдельно либо этап остаётся `verification`.
- [ ] При отказе/изъятии узла владение и принятая история сохраняются; аварийное уменьшение состава не происходит автоматически.
- [ ] Эксплуатационные инструкции содержат точный порядок, условия остановки и границы разрешений.
