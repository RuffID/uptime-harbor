Зависимости: [01](../01-protocol-and-contracts/main.md), [02](../02-domain-and-persistence/main.md), [03](../03-peer-health-and-leadership/main.md), [04](../04-revision-synchronization/main.md), [05](../05-permissions-and-ownership/main.md), [06](../06-monitoring-and-incidents/main.md), [07](../07-leader-notifications/main.md), [08](../08-web-and-administration/main.md), [09](../09-migration-and-operations/main.md).

[Общий план](../main.md) содержит сводные статусы; [требования](../business-requirements.md) и [техническое проектирование](../technical-design.md) определяют согласованное поведение. Подготовка документа не разрешает реализацию, запуск приложения, внешние проверки или включение функции.

## Затрагиваемые части проекта

`tests/UptimeHarbor.Domain.Tests`, `Application.Tests`, `Infrastructure.Tests`, `Web.Tests`, `tests/Frontend`, их локальные `AGENTS.md`, `Documentation/Technical documentation/Testing.md`. Сначала пользователь проверяет один узел на своём ПК разработчика, затем постепенно запускает продовые узлы. Ориентир — три узла и около 30 приложений с проверкой раз в минуту. Отдельный стенд на три/пять узлов не требуется.

Работа ограничена перечисленными ниже сценариями; смежные компоненты изменяются только при необходимости выполнить результат подэтапа.

## Работы

- [ ] Добавить минимальные meaningful domain/application/fake-transport тесты критичных правил: большинство/sender gate, идемпотентность и сохранность ожидающих событий, вход/активность общего администратора. Остальные тесты добавлять при конкретной необходимости; полный охват матрицы не требуется.
- [ ] Собирать production-проекты отдельно без запуска Web-хоста; проверять только затронутые проекты и зависимости. Точные команды сверить с актуальной конфигурацией до разрешённого запуска.
- [ ] Изолированные .NET-тесты запускать через Microsoft Testing Platform отдельно по проектам. Не запускать полный Infrastructure-набор при запрете БД: в нём уже есть SQLite provider tests.
- [ ] При необходимости проверить затронутую frontend-логику через разрешённый `node --experimental-strip-types --test` для `tests/Frontend/*.test.mts`, без сети, dev server или браузера. Полный frontend-набор без причины не обязателен.

- [ ] Актуализировать затронутые локальные `AGENTS.md` и фактическую техническую документацию в пределах реализованного изменения; новые документы включить в навигацию и solution.

## Проверки

Сверить команды с проектами, отделить fake/metadata от SQLite provider tests; frontend запускать только изолированно по разрешённому исключению.

[Справочная матрица](main.md#справочная-матрица-сценариев) помогает выбрать проверку при конкретной необходимости; полный прогон не обязателен. Фактическое наблюдение этой категории не подтверждает остальные сценарии.

Команды из плана не являются разрешением их запускать. Выполняются только минимальные необходимые изолированные проверки или отдельно разрешённые действия. Отсутствие необязательной внешней проверки не блокирует завершение разработки и не объявляется успешным результатом.

## Критерии приёмки

- [ ] Приложение и внешние системы не запускаются ради изолированных проверок; незапущенные категории явно открыты.
- [ ] Работы и применимые проверки подэтапа выполнены, результат и ограничения зафиксированы.
- [ ] Статус согласован с таблицами родительского этапа и общего плана; незавершённая внешняя приёмка не объявлена выполненной.
