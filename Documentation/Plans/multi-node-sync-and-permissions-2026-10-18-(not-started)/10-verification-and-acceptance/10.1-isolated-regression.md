`tests/UptimeHarbor.Domain.Tests`, `Application.Tests`, `Infrastructure.Tests`, `Web.Tests`, `tests/Frontend`, их локальные `AGENTS.md`, `Documentation/Technical documentation/Testing.md`. Работа ограничена перечисленными ниже сценариями; смежные компоненты изменяются только при необходимости выполнить результат подэтапа.

## Работы

- [ ] Поддержать meaningful domain/application/fake-transport тесты по всем новым инвариантам и протоколу, без подмены ошибок запасными ветками.
- [ ] Собирать production-проекты отдельно без запуска Web-хоста; проверять только затронутые проекты и зависимости. Точные команды сверить с актуальной конфигурацией до разрешённого запуска.
- [ ] Изолированные .NET-тесты запускать через Microsoft Testing Platform отдельно по проектам. Не запускать полный Infrastructure-набор при запрете БД: в нём уже есть SQLite provider tests.
- [ ] Frontend-набор запускать только через разрешённый `node --experimental-strip-types --test` для `tests/Frontend/*.test.mts`, без сети, dev server или браузера.

- [ ] Актуализировать затронутые локальные `AGENTS.md` и фактическую техническую документацию в пределах реализованного изменения; новые документы включить в навигацию и solution.

## Проверки

Сверить команды с проектами, отделить fake/metadata от SQLite provider tests; frontend запускать только изолированно по разрешённому исключению.

Строки [общей матрицы](main.md#матрица-обязательных-сценариев) проверяются на всех указанных уровнях. Результаты этой категории не закрывают автоматически остальные категории.

Команды из плана не являются разрешением их запускать. Непроведённая обязательная проверка остаётся открытой; готовность кода при ожидающей приёмке обозначается `verification`.
