# Этап 09. Переход существующих установок и эксплуатация

Статус: not-started

## Цель

Подготовить безопасный ввод сетки с новыми ACL и ревизиями, восстановление узлов и эксплуатационную диагностику без потери владельцев и принятых событий.

## Зависимости и границы

После этапов 02–08. Основной путь — bootstrap и присоединение узлов с пустыми общими данными. Дополнительно предусмотреть отдельный импорт непустой установки и rejoin старого узла/backup. Подготовка runbook и файлов миграции не разрешает подключение к действующей БД, запуск хоста, backup-команд или deployment.

## Затрагиваемые части проекта

Новые EF migrations и контролируемый backfill, `Infrastructure/Identity`, `Infrastructure/InfrastructureInitializationExtensions.cs`, `Services/DataBase/DataBaseCheckUpService.cs`, `BackupService.cs`, `Web/Configuration`, конфигурационные примеры; документация `Database migrations.md`, `Deployment.md`, `Configuration.md`, `Testing.md` и соответствующие `AGENTS.md`.

## Работы

- [ ] Реализовать основной ввод с пустыми общими данными: bootstrap первой сетки, проверка доверия/идентичности нового узла, snapshot принятой ревизии, replay хвоста, проверка проекций и готовность ведомого перед допуском к рабочей роли. Локальные Identity и секреты не переносить.
- [ ] Выделить импорт непустой установки из обычного join. Перед конкретной операцией получить разрешённым способом инвентаризацию и карту владельцев, сопоставить ID/имена/Telegram chat ID/привязки и показать предварительный результат без записи. После явного выбора импортировать как новые согласованные команды; не объединять пользователей по имени.
- [ ] Определить включаемые голосующие узлы, постоянные IDs, адреса, доверие peer-протокола и отдельные локальные секреты. Исключить запуск клонов БД с одинаковым NodeId.
- [ ] Описать исходный одиночный режим и controlled enable сетки; до готовности backfill не включать новые workers и ACL, способные лишить владельцев доступа.
- [ ] Описать отдельные последовательности для пустой новой сетки и непустого импорта. Для импорта: backup/подтверждение восстановления, совместимая схема, согласованное сопоставление данных, явные ACL/владельцы, проверка целостности, догон реплик, подтверждение большинства, готовность главного и включение отправки.
- [ ] Учесть нынешнее автоматическое применение миграций при старте: не считать запуск Web только проверкой компиляции и не допускать неконтролируемого применения неподготовленного backfill.
- [ ] В сценарии непустого импорта перенести текущие состояния/инциденты/outbox с явной дедупликацией delivery identity и terminal-состояний. Старые локальные workers остановить до открытия нового sender gate; пустой join не требует выдуманной карты старых инцидентов.
- [ ] Не предоставлять всем администраторам доступ автоматически. Подтвердить владельца каждой существующей сущности и независимые права сохранённых контейнеров до активации нового ACL.
- [ ] Описать join/rejoin, безопасное изменение состава, удаление узла с владельцами, восстановление потерянной БД, отставшую реплику после compaction и замену адреса/секрета.
- [ ] Для старого узла/backup до запуска рабочих процессов сверить ClusterId/NodeId, durable term/log и курсор с принятой историей. При возможности догрузить журнал, иначе восстановить только общую проекцию из актуального snapshot. Старую outbox не запускать до сверки доставки; исключить клон NodeId и воскрешение удалений.
- [ ] Определить rollback: границы совместимости старого бинарника/схемы, запрет возвращать stale accepted history, остановка отправок и согласованное восстановление. Не обещать безопасный downgrade одной БД при работающей новой сетке.
- [ ] Добавить безопасную диагностику: роль/term, состав/большинство, возраст heartbeat/readiness, committed/applied revision, pending/conflicts, backlog, terminal delivery errors и последняя успешная синхронизация.
- [ ] Подготовить инструкции локального восстановления доступа владельца без выдачи права глобального обхода обычному администратору. Аварийный сценарий не должен молча нарушать ACL/журнал.
- [ ] Обновить текущие бизнес- и технические документы только в соответствии с реально введённым поведением; сохранить планы v1 и завершённые этапы. Проверить новые/изменённые `AGENTS.md`, оглавления и solution items.

## Проверки

Изолированно на искусственных данных: bootstrap пустой сетки, join пустого узла со своим Identity, snapshot/replay без переноса паролей, отдельный разбор непустого импорта, маппинг дубликатов, отсутствие owner map, отсутствие владельца после каскада, идемпотентность backfill, старый/недопустимый clone NodeId, rejoin с журналом и после compaction, валидация конфигурации без секретов. Это не проверка production-данных.

Отдельная разрешаемая приёмка: backup/restore и миграция копий SQL Server, bootstrap трёх настоящих узлов, остановка старых workers, доступы бота к тестовым чатам, TLS/reverse proxy, rejoin отставшего узла, rollback в выбранной точке. Команды из runbook не выполнять автоматически.

## Критерии приёмки

- [ ] Основной пустой join получает общие данные и ACL синхронизацией; локальный администратор нового узла не получает автоматических прав на чужие сущности.
- [ ] Для непустого импорта есть предварительный разбор и явная карта начальных владельцев; неизвестные значения не заменены догадками. Отсутствие реальных установок для импорта не блокирует реализацию и проверку основного пустого пути.
- [ ] Старая копия не начинает проверки/отправку до сверки истории и не воскрешает принятые удаления.
- [ ] Переключение не запускает одновременно старых и новых независимых отправителей.
- [ ] Backup/restore, совместимость и восстановление проверены отдельно либо этап остаётся `verification`.
- [ ] При отказе/изъятии узла владение и принятая история сохраняются; аварийное уменьшение состава не происходит автоматически.
- [ ] Эксплуатационные инструкции содержат точный порядок, условия остановки и границы разрешений.

## Связанные вопросы

Открытых вопросов нет. Конкретные адреса/секреты узлов и, при необходимости импорта, сопоставления реальных данных являются входом разрешённой операции ввода; заранее их не угадывать.

## Результат выполнения

Реализация и ввод не начаты. Схемы, данные, конфигурация действующих установок и окружение не менялись.
