# Подэтап 08.2. Редакторы ожидающих изменений и удаления

Статус: not-started

## Цель и результат

Редактор отличает accepted configuration от Pending и показывает результат глобального удаления.

## Зависимости и границы

Зависимости: [08.1](08.1-api-dto-and-resource-pages.md).

Родительский [этап 08](main.md) задаёт общие ограничения и критерии. [Общий план](../main.md) содержит сводные статусы; [требования](../business-requirements.md) и [техническое проектирование](../technical-design.md) определяют согласованное поведение. Подготовка документа не разрешает реализацию, запуск приложения, внешние проверки или включение функции.

## Затрагиваемые части проекта

`Web/Pages/Index`, `Pages/Admin`, `Controllers`, `Controllers/Models`, `Hubs`, `Http/JsonResultMapper`, `wwwroot/ts/pages`, shared/types; Application DTO/read queries, Dashboard и administration services. Web tests и `tests/Frontend`; локальные `AGENTS.md`, фактические документы `Web application.md`, `Authentication and visibility.md`.

Работа ограничена перечисленными ниже сценариями; смежные компоненты изменяются только при необходимости выполнить результат подэтапа.

## Работы

- [ ] В редакторе отделить действующую конфигурацию от сохранённой заявки. Показывать «Ожидает синхронизации», принятие, отказ и конфликт; при offline не обещать немедленного применения.
- [ ] Добавить исправление и отмену непринятой заявки с подтверждённым результатом: применяется только последнее значение, подтверждённая отмена оставляет действующую настройку. При гонке с принятием показать принятый результат и предложить отдельную новую правку; до подтверждения не показывать отмену/замену завершённой.
- [ ] Подтверждать глобальное удаление с объяснением последствий и зависимостей. Кнопки «скрыть только у себя» и отдельного права удаления нет; Pending deletion не выдавать за завершённое на всех узлах.

- [ ] Для непринятых заявок из восстановленной старой копии показать необходимость подтверждения актуальности; автоматически их не отправлять. До показа сверить принятые/отменённые/заменённые результаты; подтверждение требует активного администратора и base revision.

- [ ] Актуализировать затронутые локальные `AGENTS.md` и фактическую техническую документацию в пределах реализованного изменения; новые документы включить в навигацию и solution.

## Проверки

Frontend stubs: offline save, исправление Б на В до принятия, отмена, гонка с принятием и потерянный ответ, pending/rejected, повтор запроса, сохранность ввода и принятие удаления на другом узле.

Общие сценарии [родительского этапа](main.md#проверки) сохраняются. Изолированные проверки подтверждают алгоритм; реальные БД, peer HTTP, процессы, браузер и Telegram учитываются отдельно в [этапе 10](../10-verification-and-acceptance/main.md).

Команды из плана не являются разрешением их запускать. Непроведённая обязательная проверка остаётся открытой; готовность кода при ожидающей приёмке обозначается `verification`.

## Критерии приёмки

- [ ] Нет ложного общего успеха или локального удаления; Pending не меняет действующие настройки в интерфейсе.
- [ ] Пользователь может исправить/отменить непринятую заявку и видит подтверждённый результат; отмена не выдаётся за откат уже принятого изменения.
- [ ] Непринятые заявки старого backup явно ожидают подтверждения; уже принятые/отменённые/заменённые не выдаются за новые Pending.
- [ ] Работы и применимые проверки подэтапа выполнены, результат и ограничения зафиксированы.
- [ ] Статус согласован с таблицами родительского этапа и общего плана; незавершённая внешняя приёмка не объявлена выполненной.
