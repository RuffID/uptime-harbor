## Работы

## Проверки

Проверить обновление статуса при смене главного и исчезновении свежих данных, отсутствие обещанного срока и кнопки повторной доставки.

Изолированно проверить stale response, reconnect, отключение аккаунта с открытым редактором и неполное покрытие; два администратора видят всю диагностику, анонимный/отключённый получают отказ. Browser/mobile — 10.4; metadata по observers сохраняется.

Общие сценарии [родительского этапа](main.md#проверки) сохраняются. Изолированные проверки подтверждают алгоритм; реальные БД, peer HTTP, процессы, браузер и Telegram учитываются отдельно в [этапе 10](../10-verification-and-acceptance/main.md).

Команды из плана не являются разрешением их запускать. Непроведённая обязательная проверка остаётся открытой; готовность кода при ожидающей приёмке обозначается `verification`.

## Критерии приёмки

- [x] Полная диагностика доступна каждому активному администратору без секретов; неисправная БД отличима от follower без peer-связи.
- [x] Подробная диагностика соблюдает границы сетка/свой узел/краткий статус; карточка показывает различия metadata по узлам без искусственного общего значения.
- [x] Интерфейс различает статус отправки, ошибку отдельного чата и потерю наблюдения; не обещает норматив Telegram-возобновления и не предлагает ручной retry.
- [x] Работы и применимые проверки подэтапа выполнены, результат и ограничения зафиксированы.
- [x] Статус согласован с таблицами родительского этапа и общего плана; незавершённая внешняя приёмка не объявлена выполненной.

## Результат выполнения

2026-10-29. Реализована безопасная общая диагностика текущего узла/главного/majority, БД, свежести/contact/lag, Pending/held/delivery backlog. Старый leader при утрате актуального consensus не выдаётся за текущего. Availability отделена от coverage, отсутствующие/устаревшие observers и различия metadata показаны по NodeId. Telegram Available/Unavailable/Unknown имеет закрытую причину и возраст, terminal failure видима без retry/countdown. Refresh/reconnect повторяет защищённые accepted/Pending/diagnostic reads, отбрасывает stale responses, 401/403 закрывает UI/SignalR. Изолированные tests проверили проекции, поздние ответы и повторные reads; регрессии session/apply/fault проверяют отзыв защищённых подписок.

Общий итог этапа: 504 .NET + 15 frontend tests, без ошибок/пропусков; четыре production compile-check без предупреждений. [Команды и ограничения](../../../Technical%20documentation/Testing.md#проверка-этапа-08). Приложение, SQL/provider tests, peers, Telegram, Docker и браузер не запускались; внешняя приёмка остаётся отдельной непроведённой категорией. Gates/default Disabled сохранены. Этапы 09/10 не начинались.
