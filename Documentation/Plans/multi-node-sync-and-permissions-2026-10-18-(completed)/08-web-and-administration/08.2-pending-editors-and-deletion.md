# Подэтап 08.2. Редакторы ожидающих изменений и удаления

Статус: completed

## Цель и результат

Редактор отличает accepted configuration от Pending и показывает результат глобального удаления.

## Зависимости и границы

Зависимости: [08.1](08.1-api-dto-and-resource-pages.md).

Родительский [этап 08](main.md) задаёт общие ограничения и критерии. [Общий план](../main.md) содержит сводные статусы; [требования](../business-requirements.md) и [техническое проектирование](../technical-design.md) определяют согласованное поведение. Подготовка документа не разрешает реализацию, запуск приложения, внешние проверки или включение функции.

## Затрагиваемые части проекта

`Web/Pages/Index`, `Pages/Admin`, `Controllers`, `Controllers/Models`, `Hubs`, `Http/JsonResultMapper`, `wwwroot/ts/pages`, shared/types; Application DTO/read queries, Dashboard и administration services. Web tests и `tests/Frontend`; локальные `AGENTS.md`, фактические документы `Web application.md`, `Authentication and visibility.md`.

Работа ограничена перечисленными ниже сценариями; смежные компоненты изменяются только при необходимости выполнить результат подэтапа.

## Работы

- [x] В редакторе отделить действующую конфигурацию от сохранённой заявки. Показывать «Ожидает синхронизации», принятие, отказ и конфликт; при offline не обещать немедленного применения.
- [x] Добавить исправление и отмену непринятой заявки с подтверждённым результатом: применяется только последнее значение, подтверждённая отмена оставляет действующую настройку. При гонке с принятием показать принятый результат и предложить отдельную новую правку; до подтверждения не показывать отмену/замену завершённой.
- [x] Подтверждать глобальное удаление с объяснением последствий и зависимостей. Кнопки «скрыть только у себя» и отдельного права удаления нет; Pending deletion не выдавать за завершённое на всех узлах.

- [x] Для непринятых заявок из восстановленной старой копии показать необходимость подтверждения актуальности; автоматически их не отправлять. До показа сверить принятые/отменённые/заменённые результаты; подтверждение требует активного администратора и base revision.

- [x] Актуализировать затронутые локальные `AGENTS.md` и фактическую техническую документацию в пределах реализованного изменения; новые документы включить в навигацию и solution.

## Проверки

Frontend stubs: offline save, исправление Б на В до принятия, отмена, гонка с принятием и потерянный ответ, pending/rejected, повтор запроса, сохранность ввода и принятие удаления на другом узле.

Общие сценарии [родительского этапа](main.md#проверки) сохраняются. Изолированные проверки подтверждают алгоритм; реальные БД, peer HTTP, процессы, браузер и Telegram учитываются отдельно в [этапе 10](../10-verification-and-acceptance/main.md).

Команды из плана не являются разрешением их запускать. Непроведённая обязательная проверка остаётся открытой; готовность кода при ожидающей приёмке обозначается `verification`.

## Критерии приёмки

- [x] Нет ложного общего успеха или локального удаления; Pending не меняет действующие настройки в интерфейсе.
- [x] Пользователь может исправить/отменить непринятую заявку и видит подтверждённый результат; отмена не выдаётся за откат уже принятого изменения.
- [x] Непринятые заявки старого backup явно ожидают подтверждения; уже принятые/отменённые/заменённые не выдаются за новые Pending.
- [x] Работы и применимые проверки подэтапа выполнены, результат и ограничения зафиксированы.
- [x] Статус согласован с таблицами родительского этапа и общего плана; незавершённая внешняя приёмка не объявлена выполненной.

## Результат выполнения

2026-10-29. Реализованы modal accepted/Pending редактор, стабильные IDs retry, реальные Replace/Cancel и replacement outcome. AlreadyDecided сохраняет победивший commit; новая правка требует явного rebase. Network failure/потеря ответа/конфликт сохраняют ввод. Delete требует глобального подтверждения и показывает известные зависимости. Read reconciliation сначала учитывает accepted outcomes; неизвестный held остаётся удержанным, ConfirmRestored создаёт Replace от текущей revision, Cancel не выпускает payload. Production Pending/reducer и frontend stubs проверили эти пути без SQL/браузера.

Общий итог этапа: 504 .NET + 15 frontend tests, без ошибок/пропусков; четыре production compile-check без предупреждений. [Команды и ограничения](../../../Technical%20documentation/Testing.md#проверка-этапа-08). Приложение, SQL/provider tests, peers, Telegram, Docker и браузер не запускались; внешняя приёмка остаётся отдельной непроведённой категорией. Gates/default Disabled сохранены. Этапы 09/10 не начинались.
