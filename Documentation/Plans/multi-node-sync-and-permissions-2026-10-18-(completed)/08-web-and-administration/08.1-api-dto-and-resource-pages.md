# Подэтап 08.1. API, DTO и страницы администратора

Статус: completed

## Цель и результат

Страницы и API дают полный доступ активному администратору и защищают секретные поля.

## Зависимости и границы

Зависимости: [05](../05-permissions-and-ownership/main.md), [07](../07-leader-notifications/main.md).

Родительский [этап 08](main.md), [общий план](../main.md), [требования](../business-requirements.md) и [техническое проектирование](../technical-design.md) задают границы. Подготовка документа не разрешает реализацию, запуск приложения или внешние проверки.

## Затрагиваемые части проекта

Razor Pages, controllers, DTO, SignalR, frontend-модули и страницы объектов/чатов/пользователей. Профильные тесты, ближайшие `AGENTS.md` и актуальная техническая документация обновлены по фактической реализации.

## Работы

- [x] Применить единую проверку активного администратора к чтению и изменениям всех объектов, пользователей и диагностики; ресурсные фильтры и формы назначения доступа исключить.
- [x] Контейнеры и серверы показывать всем администраторам; перенос, отвязка и выбор observers не требуют дополнительных разрешений.
- [x] Не передавать PasswordHash, security stamp, пароли и токены в обычные DTO/DOM/SignalR/ошибки. Использовать существующие ServiceResult/JsonResultMapper, antiforgery и безопасные model-state errors.
- [x] Выбор observers сохранять обычной заявкой; результаты и различающиеся endpoint-данные показывать по узлам без вымышленного общего значения.
- [x] Актуализировать затронутые локальные `AGENTS.md` и фактическую техническую документацию; новые документы включить в навигацию и solution.

## Проверки

Изолированно проверить реальные MVC options, antiforgery, model-state errors, direct API активным/анонимным/отключённым аккаунтом, полный список сущностей для двух администраторов и отсутствие секретов в DTO/DOM.

Изолированные проверки не подменяют SQL Server, peer HTTP, браузер и Telegram. Внешняя приёмка учитывается отдельно в [этапе 10](../10-verification-and-acceptance/main.md); команды из плана не разрешены автоматически.

## Критерии приёмки

- [x] Каждый активный администратор видит и изменяет все объекты через UI/API.
- [x] Серверная авторизация обязательна; хеши и секреты не раскрываются, таблицы отдельных разрешений отсутствуют.
- [x] Работы и применимые проверки выполнены; непроведённая внешняя приёмка остаётся открытой.
- [x] Статус согласован с родительским этапом и общим планом.

## Результат выполнения

2026-10-29. Реализованы ClusterAdministrationAccess/query/явные DTO и API /api/admin/cluster; Index/Admin выбирают единый typed cluster UI. Все активные принятые Administrator читают общие сущности, конфликты, Pending и диагностику. Legacy read/write обход в enabled отклоняется; owner/resource permissions UI удалён. Observers изменяются обычной заявкой, результаты/metadata раздельны по NodeId. Реальные MVC options, direct active/anonymous/disabled API, authorization до/после I/O, antiforgery metadata и безопасные ошибки проверены изолированно.

Общий итог этапа: 504 .NET + 15 frontend tests, без ошибок/пропусков; четыре production compile-check без предупреждений. [Команды и ограничения](../../../Technical%20documentation/Testing.md#проверка-этапа-08). Приложение, SQL/provider tests, peers, Telegram, Docker и браузер не запускались; внешняя приёмка остаётся отдельной непроведённой категорией. Gates/default Disabled сохранены. Этапы 09/10 не начинались.
