# Подэтап 06.3. Общие инциденты и намерения доставки

Статус: completed

## Цель и результат

Переходы partial/full/recovered образуют одну согласованную историю и стабильные события.

## Зависимости и границы

Зависимости: [06.2](06.2-availability-and-freshness.md).

[Общий план](../main.md) содержит сводные статусы; [требования](../business-requirements.md) и [техническое проектирование](../technical-design.md) определяют согласованное поведение. Подготовка документа не разрешает реализацию, запуск приложения, внешние проверки или включение функции.

`Domain/Monitoring`, `Application/Monitoring`, `Infrastructure/Monitoring`, новые peer health/observation сценарии, persistence инцидентов и журнала; Dashboard и SignalR read models. Тесты Domain/Application/Infrastructure; `Monitoring.md`, `Domain model.md` и ближайшие `AGENTS.md`.

Работа ограничена перечисленными ниже сценариями; смежные компоненты изменяются только при необходимости выполнить результат подэтапа.

## Работы

- [x] Хранить проблемные направления и переходы partial/full/recovered в одной общей истории цели. Готовить уведомления об изменении подтверждённой частичной доступности и её восстановлении, не повторяя одно и то же событие каждый цикл.
- [x] Формировать согласованные outage/recovery с общим incident ID, порядком событий и намерением доставки. Replay одного наблюдения не открывает повторный инцидент.

- [x] Создавать отдельные устойчивые события и intents частичной/полной потери наблюдения, изменяя их только при переходах состояния. Получателей восстановления определять по подтверждённым доставкам предупреждения с общими правилами unbind/удаления. Использовать безопасное логирование переходов без дублирования replay и секретов по контракту 01.3.

- [x] Актуализировать затронутые локальные `AGENTS.md` и фактическую техническую документацию в пределах реализованного изменения; новые документы включить в навигацию и solution.

## Проверки

Проверить переходы полное → частичное → отсутствующее → полное наблюдение, повтор неизменного состояния, смену главного и чат без успешного предупреждения.

Проверить одну аварию у трёх observers, повтор того же набора направлений, изменение partial и восстановление всех направлений.

Общие сценарии [родительского этапа](main.md#проверки) сохраняются. Изолированные проверки подтверждают алгоритм; реальные БД, peer HTTP, процессы, браузер и Telegram учитываются отдельно в [этапе 10](../10-verification-and-acceptance/main.md).

Команды из плана не являются разрешением их запускать. Непроведённая обязательная проверка остаётся открытой; готовность кода при ожидающей приёмке обозначается `verification`.

## Критерии приёмки

- [x] Повтор проверки не создаёт новый incident/event; accepted incident и intent согласованы атомарно.
- [x] Предупреждение о наблюдении не является ложной аварией цели; восстановление адресуется только предупреждённым чатам, replay не создаёт повторных intents.
- [x] Работы и применимые проверки подэтапа выполнены, результат и ограничения зафиксированы.
- [x] Статус согласован с таблицами родительского этапа и общего плана; незавершённая внешняя приёмка не объявлена выполненной.

## Результат выполнения

Реализованы стабильные incident/event/intents, отдельная coverage history и атомарный projection write set с cursor/receipt. Recovery использует только accepted successful attempt; unbind сохраняет право предупреждённого чата, удаление чата отменяет recovery. Изолированные reducer/UoW/audit tests проверили переходы, replay, отказ до/после commit и отсутствие повторного success. Production producer attempts и dispatcher не реализованы: это 07.

Фактические команды, проверки и ограничения — [Testing.md](../../../Technical%20documentation/Testing.md#проверка-этапа-06). БД/SQL/SQLite, приложение/hosting, Docker, реальные peers/endpoints/Telegram и deployment не запускались; Git не выполнялся. Fake storage не доказывает SQL semantics, локальный WAL reopen — crash/fsync или majority, статический/API test — browser acceptance. Admission/trust/activation/delivery и browser/worker/sender gates остаются закрытыми. Этапы 07–09 и самостоятельный этап 10 не начинались; после 06.4 работа остановлена.
