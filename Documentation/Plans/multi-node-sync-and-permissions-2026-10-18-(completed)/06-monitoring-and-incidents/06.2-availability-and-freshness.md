# Подэтап 06.2. Сведение доступности и свежесть

Статус: completed

## Цель и результат

Общее состояние различает available/partial/unavailable и неполное покрытие.

## Работы

- [x] Реализовать согласованное сведение наблюдений: все свежие успехи — available, успехи и подтверждённые ошибки — partial, все ожидаемые подтверждённые отказы — unavailable; отсутствие результатов отмечать отдельно. Отделить local observer state от общего monitoring state.
- [x] Применять существующий порог обычных ошибок отдельно каждому observer. Неответивший наблюдатель не является отказом самой цели; stale/неполные данные не превращают свежий успех в полный outage.
- [x] Partial обычной цели не запускает выборы исправного главного с большинством. Узел с неисправной собственной БД прекращает рабочие проверки и отражается в диагностике; возврат только после восстановления и догона.
- [x] Различать сетевой отказ, сообщённую неисправность БД/worker, общую проблему Telegram и ошибку одного чата. Не угадывать причину удалённого отказа по timeout.

- [x] Рассчитывать покрытие и доступность по назначенному набору конкретной цели. Неназначенный узел не создаёт ложный partial, а пропавший назначенный остаётся видимым отсутствием результатов. Имя приложения и время запуска/работы выводить по observers; различия не сводить к произвольному общему значению и не считать отказом.

- [x] Различать полное покрытие, частичную и полную потерю наблюдения для отдельных предупреждений. Изменение покрытия не подменяет подтверждённый отказ/восстановление цели; отсутствие свежих данных не закрывает открытую аварию.

- [x] Актуализировать затронутые локальные `AGENTS.md` и фактическую техническую документацию в пределах реализованного изменения; новые документы включить в навигацию и solution.

## Проверки

Проверить: один observer пропал при свежем успехе другого, затем пропали все, затем покрытие восстановилось; открытая авария не закрывается одним исчезновением результатов.

Проверить независимые failure counters, свежий успех при отсутствующих observers, полный отказ всех ожидаемых направлений, неисправную БД узла и смену состава. Проверить доступный только двум назначенным узлам внутренний адрес, пропавшего назначенного observer и два успешных ответа с разными именами/временами запуска.

Общие сценарии [родительского этапа](main.md#проверки) сохраняются. Изолированные проверки подтверждают алгоритм; реальные БД, peer HTTP, процессы, браузер и Telegram учитываются отдельно в [этапе 10](../10-verification-and-acceptance/main.md).

Команды из плана не являются разрешением их запускать. Непроведённая обязательная проверка остаётся открытой; готовность кода при ожидающей приёмке обозначается `verification`.

## Критерии приёмки

- [x] Пропущенное наблюдение не считается отказом цели; partial не инициирует выборы исправного главного с большинством.
- [x] Неназначенные узлы не участвуют в покрытии; различающиеся успешные metadata сохранены по узлам и не создают ложного outage.
- [x] Переходы потери/восстановления наблюдения определены отдельно от partial/full/recovered самой цели; неизменное покрытие не создаёт новое событие.
- [x] Работы и применимые проверки подэтапа выполнены, результат и ограничения зафиксированы.
- [x] Статус согласован с таблицами родительского этапа и общего плана; незавершённая внешняя приёмка не объявлена выполненной.

## Результат выполнения

Реализованы независимые per-observer thresholds, success reset и принятая freshness 2×interval+timeout+20. Available/Partial/Unavailable/Unknown отделены от покрытия; stale/missing не создаёт outage/recovery. Metadata и классы отказа сохранены по узлам. Production cycle/gates проверены fake endpoint/time: неисправная БД прекращает checks, CanConnect без ConfirmRecovery их не возвращает; Disabled не запускает новый путь. Partial не вызывает resign.

Фактические команды, проверки и ограничения — [Testing.md](../../../Technical%20documentation/Testing.md#проверка-этапа-06). БД/SQL/SQLite, приложение/hosting, Docker, реальные peers/endpoints/Telegram и deployment не запускались; Git не выполнялся. Fake storage не доказывает SQL semantics, локальный WAL reopen — crash/fsync или majority, статический/API test — browser acceptance. Admission/trust/activation/delivery и browser/worker/sender gates остаются закрытыми. Этапы 07–09 и самостоятельный этап 10 не начинались; после 06.4 работа остановлена.
