## Проверки

При отдельно выбранной проверке восстановления учитывать отставшую копию, отмену подтверждения, возврат старых узлов и restart во время обслуживания; без фактического выполнения не отмечать сценарии проверенными.

Пользователь сначала проверяет один узел на своём ПК разработчика, затем постепенно запускает продовые узлы и наблюдает работу, ошибки и нагрузку. Расширенные restore/rollback и сценарии справочной матрицы выполняются только при отдельной необходимости; их полный прогон не требуется.

[Справочная матрица](main.md#справочная-матрица-сценариев) помогает выбрать проверку при конкретной необходимости; полный прогон не обязателен. Фактическое наблюдение этой категории не подтверждает остальные сценарии.

Команды из плана не являются разрешением их запускать. Выполняются только минимальные необходимые изолированные проверки или отдельно разрешённые действия. Отсутствие необязательной внешней проверки не блокирует завершение разработки и не объявляется успешным результатом.

## Результат выполнения

Выполнено 2026-10-30 в согласованном минимальном объёме. [10.1](10.1-isolated-regression.md) завершён: четыре последовательных production build без предупреждений/ошибок, 582 .NET и 18 frontend tests успешны, без пропусков. [Новый результат и точная граница](../../../Technical%20documentation/Testing.md#проверка-этапа-10) отделены от результатов 09 и сообщения пользователя об отсутствии ошибок Visual Studio. Новых дефектов кода в этом объёме не обнаружено; исправлены устаревшие документальные описания подключённых workers/UI/lifecycle и startup Disabled/Enabled.

Подготовлен [точный порядок самостоятельной проверки](../../../Technical%20documentation/Cluster%20operations.md#самостоятельная-проверка-пк-разработчика-затем-production): один новый узел на ПК, затем production Join по одному с проверкой результата каждого изменения состава; при трёх production-узлах временный ПК удаляется согласованно. Для каждого шага указаны предпосылки, ожидаемое, остановка и диагностика. Команды только описаны. Backup/rejoin, ручное аварийное fencing, maintenance/rollback и безопасное хранение истории остаются в актуальных runbooks; их фактическое выполнение не заявлено.

10.2–10.5 остаются **not-started**, внешних результатов нет. Не проверены SQL locking/atomicity/схема/restore, crash/fsync, реальные peers/TLS/elections/partition/process failure, browser/mobile/SignalR, monitoring, Telegram, физическая изоляция, deployment и часовая цель трёх узлов/около 30 приложений. Отсутствие этих необязательных наблюдений не блокирует completed разработки. Пользовательская приёмка остаётся **не выполнена**; следующий ручной шаг — подготовка одного узла на ПК по шагу 1 runbook.

Сводные статусы, навигация и solution items синхронизированы; дата 2026-10-18 сохранена, папка плана получила completed. 01–09 не переписаны, 09.2/09.3 остаются cancelled. Default Disabled, секреты, migrations/generated model и исходные изменения сохранены. Git, SQL, приложение и команды runbook не запускались. После этапа 10 работа остановлена.
