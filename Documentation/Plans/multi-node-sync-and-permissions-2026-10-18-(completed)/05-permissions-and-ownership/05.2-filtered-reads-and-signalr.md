# Подэтап 05.2. Общий вход, чтение и SignalR

Статус: completed

## Цель и результат

Один аккаунт работает на всех догнавших узлах; чтение и SignalR доступны всем администраторам.

## Зависимости и границы

Зависимости: [04](../04-revision-synchronization/main.md), [05.1](05.1-subjects-and-resource-policies.md).

Родительский [этап 05](main.md), [общий план](../main.md), [требования](../business-requirements.md) и [техническое проектирование](../technical-design.md) задают границы. Подготовка документа не разрешает реализацию, запуск приложения или внешние проверки.

## Затрагиваемые части проекта

Infrastructure/Identity, Web login/cookie authorization, Application queries и SignalR. Профильные тесты, ближайшие `AGENTS.md` и актуальная техническая документация обновлены по фактической реализации.

## Работы

- [x] Подключить принятые общие аккаунты, защищённые данные пароля и роль к существующему Identity-входу на каждом узле. Не синхронизировать cookie и сессии.
- [x] Заменить ресурсную фильтрацию списков, поиска, counts, selectors и SignalR единой проверкой активного администратора. Все сущности видны каждому вошедшему администратору.
- [x] После применения отключения/удаления или смены PasswordHash/security stamp прекращать использование прежних данных входа и сессий, закрывать защищённые SignalR-подписки.

## Проверки

Вход тем же аккаунтом на двух узлах, видимость всех объектов, отказ анонимному/отключённому пользователю, обновление password/stamp, прекращение старой сессии и SignalR после apply, отсутствие секретов в DTO.

Изолированные проверки и compile-check не подменяют SQL Server, реальные peer HTTP, браузер и Telegram. Внешняя приёмка учитывается отдельно в [этапе 10](../10-verification-and-acceptance/main.md); команды из плана не разрешены автоматически.

## Критерии приёмки

- [x] Одна учётная запись и пароль работают на любом догнавшем узле; сессии локальны.
- [x] В списках нет персональных фильтров; защищённые данные входа не попадают в UI.
- [x] Работы и применимые проверки выполнены; непроведённая внешняя приёмка остаётся открытой.
- [x] Статус согласован с родительским этапом и общим планом.

## Результат выполнения

2026-10-29 реализованы accepted sign-in на каждом узле, локальные lockout/cookie/session epoch и node discriminator Data Protection. Вход читает только принятые активные аккаунты, без UserManager rehash и без journal записи успешного входа. Pending пароль/непринятый пользователь доступа не дают. Dashboard проверяет единую policy до чтения/поиска/counts; SignalR проверяет локальные сессии и отзывает их после apply hash/stamp/disable/delete и недостоверного recovery/fault. Обычный offline сохраняет последнее достоверное принятое состояние.

Изолированные AcceptedSignInTests/AcceptedCookieTests/AccountSessionTests вызывают production credential/login/session/cookie/reducer/apply с заменёнными storage/authentication/HubCallerContext. Подтверждены локальность lockout/сессий, отказ inactive/unaccepted/recovery, invalidation и отсутствие секретов/ложного success в проверяемых ответах и логах. Это не browser/SQL/живая сеть. Enabled browser/worker/sender gates остаются закрыты; UI этапа 08 не реализован. Сводные команды, результаты и непроверенный объём — [Testing.md](../../../Technical%20documentation/Testing.md#проверка-этапа-05).
