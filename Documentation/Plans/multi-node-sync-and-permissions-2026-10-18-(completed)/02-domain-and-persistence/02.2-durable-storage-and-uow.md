## Проверки

Проверены граница календарного года (включая високосный год) и все protection flags; terminal Pending/control, cursor, независимость observer streams, известный успех, лимит попыток и recovery entitlement — через публичную доменную модель.

EF metadata проверяет таблицы, ключи/индексы, отдельные observer streams, Restrict-связи summary/event/intent и аккаунты/роль без resource permissions. Fake-тесты вызывают фактический projection UoW: один save/commit пакета, повтор без staging, rollback/clear и повтор после ошибки, отказ при другом digest. DI проверена без worker/соединения. Выбранный Infrastructure-набор вместе с migration/legacy metadata/bootstrap: 27 успешно, 0 ошибок/пропусков.

Это проверки storage-модели и orchestration-контракта. SQL Server atomicity, crash/restart процесса, snapshot installer, общий replay/failover и реальная доставка после unbind не проверены и не выдаются за реализованный runtime.

Общие сценарии [родительского этапа](main.md#проверки) сохраняются. Изолированные проверки подтверждают алгоритм; реальные БД, peer HTTP, процессы, браузер и Telegram учитываются отдельно в [этапе 10](../10-verification-and-acceptance/main.md).

Команды из плана не являются разрешением их запускать. Непроведённая обязательная проверка остаётся открытой; готовность кода при ожидающей приёмке обозначается `verification`.

## Результат выполнения

Добавлены независимые storage-контракты Application, отдельные EF mappings и четыре сценарных UoW, проекция принятого пакета с Identity без auto-commit, локальные Pending/capture/results и retention query. Существующие вызовы адаптированы к отсутствию resource permissions; пользовательские сценарии 05 не реализованы. Подробная схема, порядок и ограничения — [Shared cluster storage.md](../../../Technical%20documentation/Shared%20cluster%20storage.md). SQL не является заменой долговременному Raft WAL.
