## Проверки

Проверены Up/Down, designer и snapshot. Изолированный `IMigrationsModelDiffer` не находит различий текущей design-time SQL Server модели и snapshot; migration operations удаляют только две таблицы permissions и не содержат InsertData/SqlOperation/backfill. Исторические migrations сверены по исходным SHA-256.

Tooling: dotnet-ef 10.0.11, runtime/Design/SQL Server 10.0.13; предупреждение о более старом patch tool зафиксировано, пакет не переустанавливался. Применение Up/Down, создание constraints и backup/restore не выполнялись. Провайдерные результаты относятся к самостоятельной внешней приёмке 10.2/10.6.

Общие сценарии [родительского этапа](main.md#проверки) сохраняются. Изолированные проверки подтверждают алгоритм; реальные БД, peer HTTP, процессы, браузер и Telegram учитываются отдельно в [этапе 10](../10-verification-and-acceptance/main.md).

Команды из плана не являются разрешением их запускать. Непроведённая обязательная проверка остаётся открытой; готовность кода при ожидающей приёмке обозначается `verification`.

## Результат выполнения

Штатным EF scaffolding создана `20261029053354_AddSharedClusterStorage`, designer и согласованный snapshot. Перед итоговым scaffolding новая неприменённая migration пересоздана разрешённым `remove --force` с factory без строки подключения: tooling получил ошибку отсутствия строки до открытия соединения и восстановил предыдущий snapshot. Опция `--offline` установленным tool не поддерживается; первоначальная команда завершилась без удаления файлов.

Генерируемые и исторические migrations вручную не правились. Default-значения новых столбцов не являются backfill для старой установки; схема предназначена для пустой БД. Down удаляет новую историю и не является процедурой cluster recovery. См. [Database migrations.md](../../../Technical%20documentation/Database%20migrations.md).
