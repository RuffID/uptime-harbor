Работа ограничена перечисленными ниже сценариями; смежные компоненты изменяются только при необходимости выполнить результат подэтапа.

## Проверки

Минимально проверить ограниченность очередей на искусственном backlog. Фактический догон пользователь наблюдает при постепенном вводе узлов; нагрузочное испытание не обязательно.

Fake transport: дубли/перестановки/пропуски, неверный пакет, лимиты и backlog; проверить минутные настройки и немедленные изменения общих аккаунтов/роли/удалений/событий без утечки данных входа.

Общие сценарии [родительского этапа](main.md#проверки) сохраняются. Изолированные проверки подтверждают алгоритм; реальные БД, peer HTTP, процессы, браузер и Telegram учитываются отдельно в [этапе 10](../10-verification-and-acceptance/main.md).

Команды из плана не являются разрешением их запускать. Непроведённая обязательная проверка остаётся открытой; готовность кода при ожидающей приёмке обозначается `verification`.

## Критерии приёмки

Отметки относятся к серверной границе и согласованным изолированным проверкам. Общий sign-in/UI, реальные SQL Server, сеть и внешняя приёмка не включены.

- [x] Ошибка не сдвигает курсор, очереди ограничены, приоритетные изменения не ждут минутного цикла.
- [x] Рабочий масштаб и часовая цель догона учтены; прогресс доступен для самостоятельного наблюдения. Непроведённое нагрузочное испытание не объявлено успешным.
- [x] Работы и применимые проверки подэтапа выполнены, результат и ограничения зафиксированы.
- [x] Статус согласован с таблицами родительского этапа и общего плана; незавершённая внешняя приёмка не объявлена выполненной.

## Результат выполнения

2026-10-29. Реализованы singleton admission gate (10000 незавершённых записей, 1000 reserved controls), bounded `PendingReplicationPump`, защищённые peer batch controller/transport и `ReplicationProgress` в peer health. Настройки идут минутным циклом; Account.*, Delete/Cancel/Replace — оперативно. Retry: 1/2/5/10/30 секунд с jitter до 20%. `RevisionBatchTests`/`PendingReplicationTests`/`RevisionBoundaryTests` проверяют whole-batch validation, неверный tail/ответ, дубли/перестановки/пропуски, actual stream/count/byte limits, bounded backlog и held backup. Ошибка ответа не разрешает Pending; cursor принадлежит committed Raft-префиксу. Ориентир три узла/около 30 приложений учтён ограничениями; incidents/delivery остаются в 06/07. Часовая цель и производительность не наблюдались.

Общий итог: отдельные production builds — 0 предупреждений/ошибок; Domain 36, Application 166, выбранные Infrastructure 65, Web Cluster/DI 22 успешно, без ошибок/пропусков. БД/SQL/provider tests, приложение/host, реальные peer/Telegram, Docker, deployment и Git не запускались. Migration не применялась. Crash/fsync, живой failover и часовая цель догона не доказаны; внешняя приёмка учитывается отдельно. Работа остановлена после 04 и 05.1.
