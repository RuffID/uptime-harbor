## Работы

- [x] Snapshot/replay включает общие аккаунты, защищённые данные пароля, статус и единственную роль: проверить ревизию, целостность, совместимость и атомарное переключение. Локальные сессии, ключи и секреты узла не заменяются; старые пароли и удалённые аккаунты не восстанавливаются поверх принятой истории.
- [x] Определить retention/compaction по подтверждениям либо обязательному snapshot-rejoin старых узлов; не удалять tombstones только по возрасту.

- [x] После restore старой копии сверять результаты её Pending с принятой историей до передачи; оставшиеся непринятые заявки удерживать до подтверждения пользователем и проверки активного администратора/base revision. Snapshot/replay не должен стирать результаты отмены/замены и восстанавливать их как новые заявки.

- [x] Отделить годовой срок завершённой пользовательской истории от безопасного retention журнала/tombstones. Защитить незавершённые события, конфликты, Pending и intents, в том числе давние сводки. Выбор snapshot/replay должен поддерживать часовую цель догона для трёх узлов и около 30 приложений с проверкой раз в минуту.

- [x] Актуализировать затронутые локальные `AGENTS.md` и фактическую техническую документацию в пределах реализованного изменения; новые документы включить в навигацию и solution.

## Проверки

Проверить очистку за пределами года при открытом инциденте, неразрешённом конфликте, Pending, ожидающей сводке и ещё не подтвердившей удаление реплике.

Проверить restore после compaction с Pending и утраченным локальным ответом об отмене/замене: восстановить результат до передачи; непринятые заявки без подтверждения не отправлять.

Проверить crash при переключении snapshot, повреждение/несовместимость, rejoin после compaction, восстановление актуальных общих аккаунтов/роли и сохранность локальных сессий/секретов/Pending без возврата старых аккаунтов или паролей.

Общие сценарии [родительского этапа](main.md#проверки) сохраняются. Изолированные проверки подтверждают алгоритм; реальные БД, peer HTTP, процессы, браузер и Telegram учитываются отдельно в [этапе 10](../10-verification-and-acceptance/main.md).

Команды из плана не являются разрешением их запускать. Непроведённая обязательная проверка остаётся открытой; готовность кода при ожидающей приёмке обозначается `verification`.

## Критерии приёмки

Отметки относятся к серверной границе и согласованным изолированным проверкам. Общий sign-in/UI, реальные SQL Server, сеть и внешняя приёмка не включены.

- [x] Snapshot переключается атомарно, удаления не воскресают, compaction допускает только безопасный догон либо обязательный snapshot-rejoin.
- [x] Восстановление старого backup не запускает Pending без сверки и подтверждения; обычный restart сохраняет штатное восстановление очереди.
- [x] Годовая очистка не теряет ожидающие доставки/заявки и не позволяет старой реплике вернуть удаления; часовая цель catch-up сохраняется для самостоятельного наблюдения без обязательного нагрузочного прогона.
- [x] Работы и применимые проверки подэтапа выполнены, результат и ограничения зафиксированы.
- [x] Статус согласован с таблицами родительского этапа и общего плана; незавершённая внешняя приёмка не объявлена выполненной.

## Результат выполнения

2026-10-29. Реализованы streaming `RevisionSnapshotStore`, `SnapshotProjectionUnitOfWork` и `RevisionClusterRecovery`. Manifest проверяет revision/term/identity/compatibility, SHA-256/chunk hashes; bounded streams/temp files ограничивают размер. Current меняется после SQL checkpoint/install. Whitelist включает accounts/hash/stamps/активность/Administrator; локальные counters, SessionEpoch, сессии, ключи, секреты и Pending сохраняются. Stale account/cursor history отвергается.

Snapshot сохраняет decisions/controls/tombstones и версии на срок generation. DotNext watermark разрешает удаление старых snapshot files при сохранённом latest; узлу без нужного WAL требуется snapshot. Календарная `HistoryRetention`/query отделена от Raft retention, cleanup worker не добавлен: незавершённая работа и необходимые сводки не удаляются. `RevisionSnapshotTests` проверяет corruption/compatibility, streaming import/overflow/temp cleanup, compaction/late original, whitelist и stale credentials; `RevisionRecoveryTests` — checkpoint failure без переключения Current и настоящий WAL replay. Два SaveChanges install находятся в одной outer transaction; SQL Server execution/process crash не проверялись.

Общий итог: отдельные production builds — 0 предупреждений/ошибок; Domain 36, Application 166, выбранные Infrastructure 65, Web Cluster/DI 22 успешно, без ошибок/пропусков. БД/SQL/provider tests, приложение/host, реальные peer/Telegram, Docker, deployment и Git не запускались. Migration не применялась. Crash/fsync, живой failover и часовая цель догона не доказаны; внешняя приёмка учитывается отдельно. Работа остановлена после 04 и 05.1.
