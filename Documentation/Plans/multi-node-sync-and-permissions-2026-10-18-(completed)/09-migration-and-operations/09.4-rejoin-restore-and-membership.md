## Работы

- [x] Описать join/rejoin, безопасное изменение состава, удаление узла без удаления общих пользователей, восстановление БД, compaction и замену адреса/секрета.
- [x] Для старого узла/backup до запуска рабочих процессов сверить ClusterId/NodeId, durable term/log и курсор с принятой историей. При возможности догрузить журнал, иначе восстановить только общую проекцию из актуального snapshot. Старую outbox не запускать до сверки доставки; исключить клон NodeId и воскрешение удалений.

- [x] Управление составом/доверием доступно любому активному администратору. Проверять аккаунт и majority до изменения данных; отдельное операторское назначение не требуется.

- [x] При восстановлении старого backup удерживать Pending до сверки OperationId с принятой историей и результатами отмены/замены. Оставшиеся непринятые заявки требуют подтверждения пользователем, активного администратора и base revision; автоматической повторной подачи нет.

- [x] Реализовать отдельную ручную аварийную процедуру при безвозвратной потере большинства: администратор выбирает сохранившуюся копию и явно подтверждает возможную потерю отсутствующих изменений. До активации исключить самостоятельную работу прежней сетки/поздно вернувшихся узлов; их возврат только контролируемым rejoin. Логировать выбор копии, подтверждение и результат без секретов по 01.3; обычный membership не обходится.

- [x] Актуализировать затронутые локальные `AGENTS.md` и фактическую техническую документацию в пределах реализованного изменения; новые документы включить в навигацию и solution.

## Проверки

Проверить потерю двух из трёх узлов, отказ от подтверждения, выбранную отставшую копию и поздний возврат обоих старых узлов; изменения вне копии не объявляются сохранёнными.

Проверить restore старого backup с принятыми/отменёнными/заменёнными и непринятыми заявками: сначала сверка, затем подтверждение оставшихся пользователем; без него передачи нет.

Проверить старые term/log/cursor, compaction, потерянную БД, clone NodeId, замену адреса/секрета и исключение узла без удаления аккаунтов. Активный администратор управляет составом, анонимный/отключённый получает отказ; majority сохраняется.

Общие сценарии [родительского этапа](main.md#проверки) сохраняются. Изолированные проверки подтверждают алгоритм; реальные БД, peer HTTP, процессы, браузер и Telegram учитываются отдельно в [этапе 10](../10-verification-and-acceptance/main.md).

Команды из плана не являются разрешением их запускать. Непроведённая обязательная проверка остаётся открытой; готовность кода при ожидающей приёмке обозначается `verification`.

## Критерии приёмки

- [x] Старая outbox закрыта до сверки, удаления не воскресают, состав не уменьшается автоматически.
- [x] Состав/доверие меняются активным администратором; уход узла не удаляет пользователей, принятую историю и роль.
- [x] Restore не воспроизводит принятые/отменённые/заменённые команды; остальные непринятые заявки ожидают подтверждения пользователя.
- [x] Аварийное восстановление без подтверждения не запускается, автоматического сокращения состава нет; старая сетка не работает параллельно с восстановленной.
- [x] Работы и применимые проверки подэтапа выполнены, результат и ограничения зафиксированы.
- [x] Статус согласован с таблицами родительского этапа и общего плана; незавершённая внешняя приёмка не объявлена выполненной.

## Результат выполнения

Реализованы принятые membership/trust intents/results с повторной accepted Administrator authorization, сверка native membership до Start и quarantined catch-up до minimum committed index. Restore сохраняет controls/results/tombstones, held Pending подтверждается только явным Replace с актуальной OperationsRevision. Ручная аварийная процедура использует выбранный committed snapshot, loss acknowledgement, пароль действующего Administrator и подтверждение специалистом фактической остановки прежних узлов/автозапуска/ingress/копий, отзыва peer trust и токена того же бота. Код проверяет полноту/подпись attestation, не физическое питание/firewall. Подготавливается только новая quarantined identity с provenance настоящих attempts и безопасным аудитом выбора/отказа/результата. [Runbook](../../../Technical%20documentation/Cluster%20recovery.md), [изолированные проверки](../../../Technical%20documentation/Testing.md#проверка-этапа-09); внешнее восстановление не выполнялось.
