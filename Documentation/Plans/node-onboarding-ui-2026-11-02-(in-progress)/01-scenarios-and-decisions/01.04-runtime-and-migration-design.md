# 01.04. Проектирование setup, runtime и переноса

## Цель и результат

Контракты runtime и migration и границы возврата в общем проектном описании.

Основание: [обзор этапа](main.md), [общий план](../main.md), [согласованный контракт](main.md#screens). При расхождении краткой задачи с полным объёмом этапа требования не ослаблять; противоречие зафиксировать до зависимой работы.

## Границы и работы

- Определить отдельную локальную identity, профиль/секреты/locks, динамический listener и поколения workers без перезапуска Web-host.
- Разделить подготовку переноса и M0–M3: shadow/delta, источник, импорт, сверку и запрет старого writer после commit.

Затрагиваемые части: Документы плана; исследованные границы Web/Infrastructure/Application Cluster. Реализация на этом этапе не поручается.

## Проверки и критерии готовности

- Setup-аккаунт второго не маскирует рабочие данные; DPAPI не требуется.
- Форматы baseline и история не создают фиктивные accepted-команды; backup/restore остаются внешней проверкой.

Доказательства и пределы подтверждения — в [исходном результате этапа](main.md#результат). Сводные числа тестов этапа не означают отдельного прогона для этого файла.
