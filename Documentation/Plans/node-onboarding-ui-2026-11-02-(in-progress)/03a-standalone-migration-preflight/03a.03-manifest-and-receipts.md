# 03a.03. Manifest, hashes и подтверждения восстановления

Статус: `not-started`. Зависимости: [03a.01](03a.01-source-inventory.md), [03a.02](03a.02-identity-mapping.md)

Это план будущей работы. Реализация и проверки по этому файлу не выполнены; запись задачи не является разрешением на внешние действия.

## Цель и результат

Строгий codec manifest и валидатор доказательств, пригодные для 03b.

Основание: [обзор этапа](main.md), [общий план](../main.md), [согласованный контракт](../technical-design.md#migration). При расхождении краткой задачи с полным объёмом этапа требования не ослаблять; противоречие зафиксировать до зависимой работы.

## Границы и работы

- Реализовать типизированный manifest: MigrationId/schema/version, partitions/hashes, counts/FK/source watermark, baseline и install/storage binding.
- Определить проверяемые backup/validated-restore receipts, их связь с источником/digest/schema и условия устаревания; UI не заменяет receipt галочкой.

Затрагиваемые части: Application migration/preflight, Infrastructure standalone persistence/UoW, Web status DTO, тесты и актуальная техническая документация.

## Проверки и критерии готовности

- Одинаковые counts при иных values/FK меняют digest и не проходят сверку.
- Stale schema/identity/backup receipt и altered manifest отвергаются; сами backup/restore здесь не выполняются.

Использовать только разрешённые статические, compile-check и изолированные проверки. Приложение, БД, Docker, сеть, браузер и Telegram этим файлом не разрешаются; внешнее подтверждение относится к этапу 07.

## Фактический результат

Не принят. При выполнении зафиксировать конкретный результат, применимые проверки и существенные непроверенные сценарии. Наличие кода или HTTP Pending само по себе не закрывает критерии.
