# Шаг 3. Инструкция инженеру и приёмка на трёх узлах

Статус — `in-progress`. Инструкция готова. Приёмку в браузере, остановку и возврат узла и проверку реальных сообщений выполняет пользователь.

## Подготовка

1. Запишите для каждого сервера его номер, адрес и `Cluster:NodeId` из локальной конфигурации. На всех трёх задайте одинаковый `Cluster:ExpectedBotId`. Токен этого бота нужен только на №1 и №2. Подготовьте тестовый чат, доступный боту.
2. Для новой установки подготовьте пустые базы с актуальной схемой. В режиме `Legacy` запустите №1 как `Bootstrap`, подпишите допуск и выполните `Activate` и `Enable`. Затем по очереди подключите №2 и №3 как `Join` с собственными идентификаторами и сертификатами. Для каждого дождитесь принятия в состав, синхронизации и допуска к работе. [Первый узел](../../../Technical%20documentation/Cluster%20operations.md#первый-узел) · [Подключение следующих узлов](../../../Technical%20documentation/Cluster%20operations.md#пустой-join-и-изменение-состава).
3. Если узел отклоняет сертификат, прочитайте причину в журнале запуска. Сверьте указанные в ошибке параметры сертификата с локальной конфигурацией и принятым удостоверением узла. Исправьте причину и подпишите допуск для нового запроса текущего запуска. Для ранее работавшего узла используйте `Restart` с прежним хранилищем. [Ошибка сертификата](../../../Technical%20documentation/Cluster%20operations.md#ошибка-сертификата).

## Сценарий приёмки

| Действие пользователя | Ожидаемый результат |
| --- | --- |
| На работающих узлах сверьте состав и общие настройки. Назначьте один доступный тестовый объект №1 и №2. На странице **Telegram** выберите **«Назначить отправителем»** рядом с №1. | В составе три ваших NodeId, большинство — два. В таблице **«Наблюдения по узлам»** появляются свежие результаты обоих наблюдателей. После принятия заявки отображается **«Назначен узел»** с NodeId №1. |
| Запишите время и остановите №1. С №2 или №3 откройте **«Диагностика узлов»** и наблюдения по тестовому объекту. | По NodeId и времени последнего контакта видна потеря связи именно с №1. Появляется результат от №2 со временем **после остановки** №1. |
| На странице **Telegram** работающего узла назначьте №2. Дождитесь отображения его NodeId. Для тестового чата один раз выберите **«Тест в очередь»** и подтвердите действие. | В таблице **«Доставки»** виден итог операции. В реальный чат приходит ровно одно тестовое сообщение. Ответ HTTP 202 означает только постановку в очередь. |
| Верните №1 в режиме `Restart` с прежним хранилищем и свежим подписанным допуском. После синхронизации и включения проверьте отправителя. Затем вручную назначьте №1 и поставьте в очередь новый тест. | До ручного выбора отображается NodeId №2. После принятия заявки отображается NodeId №1. Для нового теста в чат приходит ровно одно сообщение. |

**Результат приёмки ожидается от пользователя.** По завершении запишите, прошли ли все четыре пункта. При расхождении укажите пункт, узел, время и фактический результат.
