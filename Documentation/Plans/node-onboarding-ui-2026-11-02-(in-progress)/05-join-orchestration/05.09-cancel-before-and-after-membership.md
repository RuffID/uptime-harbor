# 05.09. Остановка до и после membership

Статус: `not-started`. Зависимости: [05.01](05.01-durable-coordinator.md), [05.05](05.05-membership-coordination.md)

Это план будущей работы. Реализация и проверки по этому файлу не выполнены; запись задачи не является разрешением на внешние действия.

## Цель и результат

Честные stop/remove ветки без мгновенного rollback принятого состава.

Основание: [обзор этапа](main.md), [общий план](../main.md), [согласованный контракт](../technical-design.md#enrollment). При расхождении краткой задачи с полным объёмом этапа требования не ослаблять; противоречие зафиксировать до зависимой работы.

## Границы и работы

- До принятого RequestMembership принять cancellation, закрыть grants/credentials/nonvoter и освободить слот, сохранив storage/source.
- При принятом/неизвестном membership сначала reconcile под lock; для voter использовать обычное контролируемое removal с majority.

Затрагиваемые части: Application Join coordinator/UoW, Infrastructure snapshot/recovery/membership, Web lifecycle/status и изолированные тесты.

## Проверки и критерии готовности

- Гонка cancel/AddMember, late callback, timeout и потеря quorum не удаляют SQL/WAL/действующего voter.
- Статус CancelDeferred не выдаётся за отмену; success не пишется до принятого результата.

Использовать только разрешённые статические, compile-check и изолированные проверки. Приложение, БД, Docker, сеть, браузер и Telegram этим файлом не разрешаются; внешнее подтверждение относится к этапу 07.

## Фактический результат

Не принят. При выполнении зафиксировать конкретный результат, применимые проверки и существенные непроверенные сценарии. Наличие кода или HTTP Pending само по себе не закрывает критерии.
