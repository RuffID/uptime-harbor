# 04.06. Enrollment E1–E4 и двусторонние probes

Статус: `completed` (2026-11-15). Зависимости: [04.01](04.01-preflight-recheck.md)

Работа возобновлена по прямому поручению пользователя. Подтверждён изолированный объём E1–E4; внешняя приёмка остаётся в 07, весь этап 04 ещё не завершён.

## Цель и результат

Подтверждённый ограниченный E4 без ложного полного Join.

Основание: [обзор этапа](main.md), [общий план](../main.md), [согласованный контракт](../technical-design.md#enrollment). При расхождении краткой задачи с полным объёмом этапа требования не ослаблять; противоречие зафиксировать до зависимой работы.

## Границы и работы

- Проверить уже подключённые descriptor/capabilities/canonical CSR/PoP, reserve/issue/bind/admit и InstallTrust по прежним IDs/key/digests.
- Проверить same-origin/no-redirect/DNS policy, limits, SQL intent перед content-addressed manifest и две peer TLS-пробы с узкой pending session.

Затрагиваемые части: Application trust/admission, Infrastructure Installation/Cluster/Identity/crypto/HTTP, Web setup/enrollment, тесты и актуальная техническая документация.

## Проверки и критерии готовности

- Wrong origin/CA/SAN/pin/ClusterId/CSR/size/digest и односторонняя связь не дают trust/admission успеха.
- E4 разрешает лишь ограниченный nonvoter/probe; snapshot/membership/Ready остаются за 05.

Использовать только разрешённые статические, compile-check и изолированные проверки. Приложение, БД, Docker, сеть, браузер и Telegram этим файлом не разрешаются; внешнее подтверждение относится к этапу 07.

## Фактический результат

Прослежены production preparation → authenticated discovery/descriptor → canonical CSR/PoP/nonce → accepted reserve/authorize/bind/admit → InstallTrust → forward/reverse peer probes. Same-origin fixed routes/system TLS, отсутствие redirect/cookies/proxy, DNS policy на каждом dial и лимиты проверены кодом и изолированными transport/crypto tests. Journal сохраняет исходные command IDs и DER до ответа; повтор и новый процесс сохраняют request/key/CSR/digests/reservation/IssueId/DER, resume ждёт прежнюю lease.

До исправления новый EnrollmentDescriptorTests подтвердил шесть пропущенных отказов: замена IssueId, serial/template или DER действительным leaf от прежнего issuer; Admitted без leaf; voter или Activated под видом ограниченного admission. После точечных проверок все варианты отклоняются. До Bind ответы read-state/resume/process-renew в CertificateAuthorized ещё могут не содержать DER: клиент сохраняет проверенный descriptor с ранее полученным public artifact и отвергает последующую подмену. Отдельно подтверждено продолжение после задержанного Bind с необходимым process renewal.

InstallTrust фиксирует SQL intent до content-addressed файла; тестовый BeforeSave проверяет отсутствие файла на границе сохранения. Проверены повреждение/отсутствие файла, ref/digest, orphan и повтор того же intent. Прерывание Bind и каждого направления peer отдельно не даёт успешной E4 evidence; повтор использует прежнюю identity/DER. Уже принятый E3 nonvoter и trust-файл могут оставаться для продолжения, но не означают завершение E4.

Неверные origin/capability/CA/SAN/pin/ClusterId/CSR/size/digest, nonce/process replay и отозванная delegation дают отказ. При успешных двух пробах сохраняется LocalPrepared, nonvoter без activation и закрытый CommonOpen. Реальный PeerBoundaryMiddleware с активной pending TLS session отвергает обычные Raft/commands/snapshot/common endpoints; runtime не создаётся, sender authority закрыта. Snapshot/grant/membership/Ready и полный Join не реализовывались.

Проверки: **Infrastructure — 104 успешно (100 enrollment + 4 limiter/compatibility); Web — 13 успешно; 0 ошибок и 0 пропусков**. Это только точные затронутые классы, не полный Infrastructure-набор. Production Infrastructure/Web и оба test-проекта собраны отдельно без restore, 0 предупреждений/ошибок; TypeScript в Web compile-check заблокирован. [Точные фильтры, команды и ограничения](../../../Technical%20documentation/Testing.md#enrollment-e1e4-0406-2026-11-15).
