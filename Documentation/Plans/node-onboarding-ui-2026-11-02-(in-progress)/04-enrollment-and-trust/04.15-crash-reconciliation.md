# 04.15. Crash: SQL, файлы, WAL и DER journal

Статус: `in-progress`. Зависимости: [04.04](04.04-storage-seal-lifecycle.md), [04.06](04.06-enrollment-through-e4.md), [04.08](04.08-remote-issuer-routing.md), [04.12](04.12-online-process-exchanges.md), [04.13](04.13-joined-managed-restart.md)

Работа этапа 04 приостановлена по просьбе пользователя. Декомпозиция не разрешает запуск проверок или продолжение кода. Указанный статус отражает точку остановки, а не принятие задачи.

## Цель и результат

Восстановимые границы trust/admission и безопасные отказы при повреждении.

Основание: [обзор этапа](main.md), [общий план](../main.md), [согласованный контракт](../technical-design.md#enrollment). При расхождении краткой задачи с полным объёмом этапа требования не ослаблять; противоречие зафиксировать до зависимой работы.

## Границы и работы

- Закрыть crash/reconciliation между accepted authorize, durable DER, Bind, SQL intent, manifest publication, probes и grant consumption.
- Проверить lost responses/replay/restart с прежними IDs/key/digests и controlled orphan cleanup/revocation без нового допуска.

Затрагиваемые части: Application trust/admission, Infrastructure Installation/Cluster/Identity/crypto/HTTP, Web setup/enrollment, тесты и актуальная техническая документация.

## Проверки и критерии готовности

- Повтор IssueId даёт те же DER; частичный SQL/file/WAL state не становится Ready.
- Доказательства из fake UoW/local WAL не выдаются за SQL/fsync/ACL/power-loss; успех не пишется при rollback.

Использовать только разрешённые статические, compile-check и изолированные проверки. Приложение, БД, Docker, сеть, браузер и Telegram этим файлом не разрешаются; внешнее подтверждение относится к этапу 07.

## Фактический результат

Не принят. При выполнении зафиксировать конкретный результат, применимые проверки и существенные непроверенные сценарии. Наличие кода или HTTP Pending само по себе не закрывает критерии.
