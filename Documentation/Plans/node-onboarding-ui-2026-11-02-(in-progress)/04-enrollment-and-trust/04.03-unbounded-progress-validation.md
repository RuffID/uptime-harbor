# 04.03. Проверка растущей истории steps

Статус: `completed`. Зависимости: [04.01](04.01-preflight-recheck.md)

Работа возобновлена по поручению пользователя. Подэтап реализован и проверен 2026-11-15; весь этап 04 остаётся незавершённым.

## Цель и результат

Проверка progress без искусственного предела срока жизни установки.

Основание: [обзор этапа](main.md), [общий план](../main.md), [согласованный контракт](../technical-design.md#enrollment). При расхождении краткой задачи с полным объёмом этапа требования не ослаблять; противоречие зафиксировать до зависимой работы.

## Границы и работы

- Заменить ограничение 10000 steps в LocalSetupAccountStore.ValidateProgressAsync безопасным bounded чтением всей необходимой истории.
- Сохранить порядок/CAS/identity/digest и обнаружение разрывов, дублей и повреждения; не обрезать историю для прохождения проверки.

Затрагиваемые части: Application trust/admission, Infrastructure Installation/Cluster/Identity/crypto/HTTP, Web setup/enrollment, тесты и актуальная техническая документация.

## Проверки и критерии готовности

- Fixtures: <10000, ровно 10000 и >10000 steps, corruption на границе страницы/в конце.
- Долгая законная установка не отвергается из-за размера, память ограничена размером страницы.

Использовать только разрешённые статические, compile-check и изолированные проверки. Приложение, БД, Docker, сеть, браузер и Telegram этим файлом не разрешаются; внешнее подтверждение относится к этапу 07.

## Фактический результат

Регрессионный тест сначала выполнен на прежней реализации: корректные 10001 шагов отвергнуты с ForeignLocalAttemptStep. Ошибка подтверждена выполнением production ValidateProgressAsync над подставным DbSet без БД.

Take(10001) и общий лимит 10000 заменены keyset-обходом всех LocalStepRecord страницами по 256, AsNoTracking, OrderBy(Id) и Id.CompareTo(cursor) > 0. Порядок cursor и сортировка принадлежат одному SQL provider; OFFSET и накопление всех страниц не используются. Нельзя исключать чужие попытки фильтром: каждая строка проходит прежние identity/evidence/digest/revision проверки. Отмена проверяется при чтении и внутри страницы. Первичный ключ Id, форматы, CAS и запись истории не менялись; при штатном startup до writers обход не пропускает и не повторяет строки.

Добавлены ProgressValidationFixture/ProgressValidationTests в существующий Installation test namespace; MemoryContext/DbSet исполняет фактические запросы store над памятью. Проверены 0/1/255/256/257/9999/10000/10001/10240 шагов, обратный исходный порядок, полный обход ровно один раз и размер каждой страницы ≤256. Corruption на позициях 255/256/10000 проверяет digest, чужую попытку и payload ID; отдельно проверены будущие revisions/generation, неверный kind, отсутствие evidence, повреждённый JSON, foreign attempts, fixed OperationIds, online lifecycle и отмена между страницами. Фактические page expressions переведены SQL Server provider через ToQueryString при закрытом соединении.

Production Infrastructure и Infrastructure.Tests собраны отдельно: 0 предупреждений, 0 ошибок. Точный ProgressValidationTests-фильтр: **32 успешно, 0 ошибок, 0 пропусков**. Другие наборы не запускались. [Команды и границы](../../../Technical%20documentation/Testing.md#история-steps-0403-2026-11-15).

Проверены размер изменённого store и новых test files (ниже 20000 байт), размещение в существующей ответственности Installation, локальные AGENTS и актуальное техническое описание. Новые документы и schema/migrations не добавлялись. SQL не выполнялся; реальная БД, provider ordering/locking, конкурентные записи, Web-host, сеть и Ubuntu/fsync не проверялись. Следующий подэтап — [04.04](04.04-storage-seal-lifecycle.md).
