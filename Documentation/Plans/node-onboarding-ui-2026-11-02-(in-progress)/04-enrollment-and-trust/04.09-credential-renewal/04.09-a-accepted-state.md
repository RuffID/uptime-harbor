### A выполнена — 2026-11-18, NUI-04-20261117-02

Завершена только accepted-часть A. Ротация хранится отдельно от invitation/attempt в прежнем RevisionImage/WAL/snapshot: immutable intent, schema-3 Authorize/Bind/RetireOldCredential, CredentialRevision по accepted Bind index, неизменные identity/template/DER, текущий ключ/revision и единственный незавершённый переход. Bind создаёт OperationalCredential прежним write set без membership change. Overlap ограничен min(Bind+24 часа, old expiry); policy закрывает старый credential на точной границе даже без Retire. Replay не меняет DER/revision/deadline. Retirement хранится отдельно от compromise revocation.

Завершены strict envelope/codec/mixed payload проверки, snapshot decision links/цепочка revision/ключей/recovery ancestors и historical DER/SPKI/fingerprint/template validation. Audit CertificateAuthorized/Bound/Retired/Rejected проверяет accepted result/границу состояния, дедуплицирует replay и не пишет DER/SPKI/proof. Новые rotation-команды в production RevisionDispatcher явно закрыты до prepare/replication с VoterCredentialRenewalAuthorityUnavailable: SystemSource/stamp/digest сами authority не дают.

Финально: Application **124 успешно** (76 новых +48 regression), Infrastructure **18 успешно** (13 новых +5 regression), в обоих 0 ошибок/пропусков. Четыре отдельные compile-check Application/Infrastructure и их test-проектов — 0 предупреждений/ошибок. Проверки in-memory/local crypto/snapshot/WAL regression, без БД/сети/хоста; native WAL именно ротации не проверялся. После итоговых прогонов C# не менялся. Локальные AGENTS и актуальная техдокументация обновлены, UTF-8/EOL/размеры/ссылки/solution items проверены. [Команды, матрица и ограничения](../../../../Technical%20documentation/Testing.md#voter-credential-rotation-0409a-2026-11-18), [текущее устройство](../../../../Technical%20documentation/Onboarding%20contracts.md#accepted-ротация-credential-voter-0409-a).

Новых migrations нет, существующие не применялись. БД (включая SQLite), приложение, сеть, Docker, браузер, Telegram, Git и deployment не использовались. Реальные UI/Ubuntu/SQL/TLS/fsync/majority не подтверждены; UI-приёмка ожидает пользователя в 07. A не включает HTTP/runtime renewal, local key install или ContinueCredential.

**Следующее отдельное назначение — B:** старый PoP и новый CSR; majority/remote signer с exact accepted authorization и прежним DER journal; durable локальный intent/key/install CredentialRevision и recovery прерванной установки; взаимная проверка/RetireOldCredential и подключение policy на всех trust/TLS boundaries. Запрет dispatcher снимать только после полноценной authority, без продления expired leaf или смены identity при outage. C затем отдельно добавляет common admin reauthentication/accepted proof для ContinueCredential. B/C и 04.10 здесь не начаты; родитель 04.09 и этап 04 остаются `in-progress`.
