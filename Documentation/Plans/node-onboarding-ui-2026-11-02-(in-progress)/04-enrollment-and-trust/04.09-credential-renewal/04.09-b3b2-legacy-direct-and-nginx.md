### Legacy Direct typed transport B3b2 — NUI-04-20261118-13

На caller первый typed запрос использует свежий TLS с системным serverAuth, hostname и online revocation. `PlaintextStreamFilter` сверяет именно два предъявленных leaf. После fresh accepted evidence транспорт закрепляет наблюдение за локальным сертификатом и NodeId/storage/address issuer. Отдельный HTTP/1.1 handler допускает в пул только эту пару и точную системную серверную цепочку. Перед выдачей запроса в пул выполняются повторные online chain/CRL и accepted lookup. Каждый новый handshake снова проверяет имя, цепочку и предъявленную пару. При потере pin или отказе повторной проверки цепочки текущий вызов завершается и соответствующий пул закрывается. Отдельный следующий вызов может получить новое проверенное наблюдение. Обычные legacy RPC идут через прежний handler с минутным сроком жизни соединения, без redirect, cookies и proxy. Повторная сериализация typed тела закрыта прежним контрактом.

На issuer legacy Direct middleware сохраняет peer listener, HTTPS, точный Host, лимиты, client CA/EKU/SAN, online CRL, accepted envelope и replay gate. Дополнительно `ISslStreamFeature` Kestrel показывает local/remote leaf текущего mTLS. Удостоверенный входящий client leaf должен совпасть с remote leaf. Local leaf разрешается по fingerprint и точному accepted voter, его ID уходит в reply. Issuer service проверяет ID и fingerprint обоих leaf и актуальные полномочия до и после signer. TLS resumption и renegotiation отключены на legacy Direct listener и typed клиенте. HTTP reuse остаётся доступен.

| Изолированная проверка | Результат |
|---|---|
| Допустимый typed вызов со старым и новым issuer leaf при overlap | Каждое наблюдение закрепляет ID предъявленного leaf. Отдельный тест issuer service с in-memory зависимостями подтверждает допустимый вызов с обоими ID/fingerprint и одну запись signer |
| Свежий вызов, новое соединение фиксированного пула и reuse | HTTP double фиксирует 3 отправки при 2 handshake callbacks. Проверка цепочки вызывается при обоих обращениях к пулу. Обычный вызов идёт через отдельный handler |
| Exact overlap boundary, accepted revocation, ошибка CRL или CRL revoked | Текущий вызов прекращается до HTTP. Пул закрывается. Граница проверена и на issuer service |
| Чужой client/server leaf, другой reply ID, неверное сочетание server ID/fingerprint | Запрос или ответ отвергается. На проверке issuer evidence журнал signer не изменяется |
| Цепочка сменилась на новом handshake, нет chain proof, платформа отклонила имя или цепочку | Typed HTTP не начинается. Свойства обычного, fresh и pooled handlers проверены отдельно |
| Managed Direct, legacy proxy, listener perimeter, signing evidence и single-write body | Затронутая изолированная регрессия проходит |

### Legacy Direct trust B3b2 — NUI-04-20261118-14

**Результат.** B1 Authorize, signer, проверка DER и локальный pre-Bind разрешают прежний P-256 leaf ручного CA для принятого legacy Direct voter. Проверяются exact old ID/DER/fingerprint/SPKI, cluster/generation, voter/storage/address/revision, PoP/CSR/nonce/process, CA/EKU/SAN/expiry и прежняя online CRL. Недоступность CRL закрывает Authorize, подпись и отправку Bind. После committed Bind восстановление result проверяет exact новый credential и accepted decision с индексом и digest. Старый leaf больше не нужен для повтора уже принятого Bind. Ручной leaf сохраняет допуск в overlap через online CRL.

Для нового leaf listener и каждый входящий RPC проверяют accepted Bind, issuer epoch/purpose, exact issuer DER/SPKI, credential, CA/EKU/SAN и accepted expiry/revocation. Исходящий typed Direct выполняет ту же dedicated проверку при установлении соединения и повторно перед reuse. TLS hostname и exact pin обоих leaf обязательны. Предварительная TLS policy исключает сетевые загрузки. Ручной server leaf использует зафиксированную системную serverAuth цепочку с online CRL, а ручной client leaf использует настроенный client CA с online CRL. Dedicated branch проверяет цепочку локально. Отказ выбранной политики конечен. Прежний обычный исходящий handler используется для нетипизированного трафика до подключения штатной смены credential.

| Проверка | Доказательство |
| --- | --- |
| Старый manual leaf и полный локальный путь до Bind | Реальные локальные P-256/CSR/CA/leaf, double статуса CRL, accepted reducers, signing journal и Bind transport в памяти. Authorize, signing, artifact и pre-Bind проходят с тем же принятым ключом. |
| CRL и потерянные ответы | Ошибка CRL/отзыв останавливают Authorize и signing. Недоступность перед Bind останавливает Send. Реальная X.509 policy отклоняет локальный manual leaf без CRL. Retry signer возвращает прежний DER с одной записью журнала. Потерянный ответ Bind восстанавливается после reopen без второго Send при недоступной CRL. |
| Переход к dedicated trust | До Bind новый leaf отвергается. После committed Bind новый leaf принимают политика входящего Direct и исходящего typed Direct. Сверены exact peer ID, overlap и отказ после границы, accepted отзыв и expiry, подмена issuer с тем же epoch, чужой purpose и отсутствие Bind result. |
| Входящий запрос и reuse | Middleware с подставным HttpContext принимает новый dedicated leaf и отказывает при неверном ID и после отзыва. Изолированный callback исходящего pool перепроверяет accepted revocation. Реальные TLS-сессии, sockets и CRL responder остаются 07.04. |

### Nginx-граница B3b2 — NUI-04-20261118-15

Согласованный [runtime-контракт](../../technical-design.md) оставляет `NginxIsolatedHttp` с завершением peer mTLS и проверкой CRL на proxy ручным путём. Автоматический путь использует Direct либо заранее подготовленный TCP TLS passthrough. В прозрачном режиме Kestrel по-прежнему завершает TLS и применяет те же проверки обоих leaf, accepted trust и reuse. Прежняя текущая запись об открытой интеграции typed RPC через proxy-terminated режим уточнена по этому контракту.

`PeerBoundaryMiddleware` явно требует Direct для `RENEW` и проверяет HTTPS до `UseForwardedHeaders`. `PeerClientHandler` отклоняет typed connection binding вне Direct до отправки. Для обычных legacy RPC остаются действующие проверки изолированного peer-порта, точного IP proxy, результата mTLS, certificate header и accepted pin. Nginx отвечает за CRL и ручную настройку trust. Противоречий, требующих нового бизнес-решения, не обнаружено.

| Проверка | Результат |
| --- | --- |
| Входящий typed renewal | В `NginxIsolatedHttp` HTTP с forwarded headers и синтетический HTTPS с доверенными proxy headers получают 403. В Direct внутренний HTTP получает 403, HTTPS только с proxy headers без TLS client certificate — 401. Запросы завершаются до контроллера. |
| Ручной legacy ingress | На прежнем health endpoint точный proxy IP, `SUCCESS` и принятый leaf проходят аутентификацию. Тестовый POST получает 405 с peer reply envelope после проверки. Другой IP при forwarded IP из allowlist, неуспешный mTLS или отсутствие certificate header дают 401. Чужой leaf даёт 403. |
| Исходящий proxy | Запрос с обязательной привязкой отклоняется до HTTP и при Legacy, и при Setup. Обычный Legacy запрос через прежний handler проходит в double. |
| Direct и предпосылка passthrough | Проверка конфигурации требует HTTPS для Direct и HTTP для `NginxIsolatedHttp`. Изолированная регрессия Direct проверяет typed routing, оба leaf, accepted evidence, CRL policy, overlap и reuse с doubles. Production composition оставляет renewal service закрытым. |
