### Managed Direct reuse B3b2 — NUI-04-20261118-12

Проверенное свежее TLS-соединение обычного peer RPC или typed renewal даёт точный server ID/fingerprint после прежних DNS/name/chain проверок, проверки обоих фактических leaf и разрешения предъявленного server leaf из accepted registry. Источник pin уже существует, поэтому отдельный запрос или новый протокол не требуются. Первый подтверждённый pin заполняет пустой слот, привязанный к локальному снимку и NodeId/storage/address. При двух первых наблюдениях каждый запрос проверяется по своему handshake. Наблюдение проигравшего запроса сохраняет только его собственную привязку. Следующее соединение пула отдельно подтверждает ту же пару leaf. TLS resumption отключён. [Текущий контракт](../../../../Technical%20documentation/Onboarding%20contracts.md#voter-credential-typed-direct-0409b3b2).

Typed caller до передачи в пул повторяет exact accepted и срок pin, срок и допустимость своего снимка, SHA-256 из renewal proof и signing evidence на актуальном срезе. При новом handshake фильтр сверяет оба leaf до первого HTTP. После заголовков ответа сверяются exact registry, сроки и ID в envelope. После чтения тела и fresh majority barrier повторно проверяются accepted signing evidence, артефакт и актуальность среза. При смене accepted среза сравниваются его относящиеся к запросу полномочия. Смена поколения до dispatch и после ответа закрывает запрос.

Утрата exact accepted записи, истечение срока или другой удостоверенный server leaf той же accepted voting identity на новом handshake инвалидируют точный слот и закрывают его handler. Текущий RPC возвращает отказ. Следующий отдельный вызов с пустым слотом может воспользоваться существующим свежим путём. Поздний callback старого слота не заполняет новый. Сетевой отказ, чужой leaf или ID из ответа не устанавливают pin. Typed тело допускает одну сериализацию к потоку транспорта. Повторная отправка запроса при отказе приложения отсутствует.

| Изолированная проверка | Подтверждённый результат |
|---|---|
| Обычный защищённый вызов, затем typed RPC с новым соединением пула и reuse | Передача в один фиксированный пул. У последующего запроса нет handshake callback, его exact credential и полномочия проверяются независимо |
| Два первых защищённых наблюдения разных leaf в overlap | Оба запроса подтверждают собственный leaf. Первый подтверждённый pin закрепляет пул, поздний ответ не смешивает пару |
| Trusted другой leaf на новом handshake, expiry X.509 или потеря accepted pin до отправки | Отказ до HTTP в текущем вызове. Handler закрыт. Следующий независимый вызов удостоверяет leaf заново и может создать новый пул |
| Потеря accepted pin после отработавшего HTTP и позднее наблюдение в инвалидированном слоте | Ответ отвергнут, счётчик отправок не увеличивается повторно. Прежнее наблюдение не заселяет новый слот |
| Другой client leaf, неподтверждённый server leaf или другой ID из reply | Привязка отклоняется, доверенный pin не меняется |
| Изменение local generation до dispatch или после отправки | Запрос со старым захватом закрывается. Новый снимок использует отдельный слот и отдельную пару |
| Изменение accepted результата между отдельным RPC по уже существующему соединению и fresh barrier | Web caller отвергает артефакт. Сохраняется одна запись signer в journal |
| Попытка повторной сериализации тела | Второй поток получает ноль байтов. Double не вызывает signer |

**Проверенные альтернативы.** Accepted Bind, issuer epoch или локальное B2b2 confirmation не различают реально предъявленный leaf при overlap. Pin по одной записи на адрес или по ID из ответа не удостоверяет соединение. Отдельный probe добавил бы I/O и также потребовал бы обязательной проверки exact leaf в каждом новом соединении. Привязку через произвольный `HttpClient` и `PlaintextStreamFilter.InitialRequestMessage` на каждом запросе ограничивает [граница API ниже](#voter-credential-typed-direct-0409b3b2). Здесь доказательство относится ко всем соединениям конкретного handler, с обязательной проверкой при допуске каждого нового соединения.
