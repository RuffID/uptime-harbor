Статус: `completed`. Зависимости: [04.02](04.02-restart-mode-before-effects.md), [04.04](04.04-storage-seal-lifecycle.md)

Выполнено 2026-11-15 по поручению продолжить план и запускать только затронутые тесты. Изолированные проверки не заменяют внешнюю приёмку этапа 07.

## Цель и результат

Подтверждённый путь нового первого с приглашением и без преждевременного открытия UI.

Основание: [обзор этапа](main.md), [общий план](../main.md), [согласованный контракт](../technical-design.md#enrollment). При расхождении краткой задачи с полным объёмом этапа требования не ослаблять; противоречие зафиксировать до зависимой работы.

## Границы и работы

- Проверить уже подключённый exact genesis intent/permit, карантинный singleton, отдельный common account, barrier/ProcessEpoch/activation/Enable.
- Проверить durable отзыв setup до CommonOpen и production issuance текущей schema3; устранять только дефекты этого сценария.

Затрагиваемые части: Application trust/admission, Infrastructure Installation/Cluster/Identity/crypto/HTTP, Web setup/enrollment, тесты и актуальная техническая документация.

## Проверки и критерии готовности

- Потеря ответа и restart не создают второй genesis/account; ранний доступ и stale permit отвергаются.
- Итоги Web 28+1 на остановке не подменяют проверку изменённого среза; поддержка существующего manual cluster здесь не заявляется.

Использовать только разрешённые статические, compile-check и изолированные проверки. Приложение, БД, Docker, сеть, браузер и Telegram этим файлом не разрешаются; внешнее подтверждение относится к этапу 07.

## Фактический результат

Путь нового первого подтверждён в изолированном объёме; дефектов production-кода в проверенных сценариях не найдено. Добавлены 17 проверок: 13 ManagedBootstrapRecoveryTests и четыре новых случая ManagedInvitationTests. Общие fixtures получили счётчики native effects и управляемые границы до/после подставного commit; production код не менялся.

- Ответ теряется после каждого из семи committed шагов: InitializeCluster, BootstrapAccount, RegisterOnlineProcess, authorize/consume activation и authorize/consume Enable. Повтор доводит прежнюю попытку до CommonOpen с ровно семью native effects, одним genesis/account/issuer/credential и прежними IDs/key reference; ProcessEpoch не повышается внутри того же процесса.
- Прямой вызов SetupBoundaryMiddleware на каждом промежуточном этапе подтверждает закрытый common UI. Подставной commit приостановлен перед завершением отзыва setup; CommonOpen остаётся закрытым. При публикации проверяются commit, Disabled, удалённый hash, новый stamp/epoch; затем common route открывается, setup route закрывается с 404.
- Потерянный ответ commit отзыва setup оставляет текущий CommonOpen закрытым при durable ClusterReady. Sealed restart сохраняет genesis/account/issuer, отвергает старый bootstrap payload до нового Enable и получает новый ProcessEpoch. Ошибка последующей публикации Ready оставляет FailedNeedsAction и не восстанавливает setup credential.
- InvitationAdministration проходит настоящий Pending/dispatcher/WAL/reducer по schema3 после Bootstrap и sealed Restart. Setup identity и неверный common password дают отказ без Pending/native effect. Потеря ответа выдачи сохраняет один accepted результат; повтор не раскрывает code и не выполняет новую запись. Явная замена выдаёт новый код и отзывает прежнее приглашение.

Финальный затронутый Web-фильтр: **59 успешно, 0 ошибок/пропусков**. Compile-check Web.Tests с зависимостями — без предупреждений/ошибок. После замены var на явные типы в invitation tests повторены build и только ManagedInvitationTests: **5 успешно, 0 ошибок/пропусков**. [Точные команды и ограничения](../../../Technical%20documentation/Testing.md#bootstrap-и-приглашение-0405-2026-11-15).

Ранний прерванный Bootstrap до первого seal проверен только на безопасный отказ без нового genesis/account. Его автоматическое resume не реализовано и не объявляется проверенным; crash/reconciliation остаётся открытым объёмом этапа 04. SQL commit/rollback/locking, fsync/power loss, настоящий второй OS-процесс, majority/elections, browser rendering и сеть не проверялись. Существующий manual cluster и полный Join здесь не подтверждаются. Исторические результаты и завершённые подэтапы не менялись.
