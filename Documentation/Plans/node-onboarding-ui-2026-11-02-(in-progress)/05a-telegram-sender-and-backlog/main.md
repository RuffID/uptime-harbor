# Шаг 2. Ручное переключение Telegram

Статус — `not-started`. [Шаг 1](../04-enrollment-and-trust/main.md) выполнен. Сейчас право отправки привязано к лидеру кластера. Инженеру нужно иметь возможность назначить отправителя, даже когда лидером выбран №3.

## Задание

Обычно сообщения отправляет №1. При его отказе инженер вручную передаёт отправку №2. В каждый момент право отправлять имеет один выбранный узел. При смене лидера и после возвращения №1 выбор сохраняется, пока инженер сам не переключит отправку обратно. На №3 отправка запрещена, токен бота отсутствует. До ручного переключения допустима пауза в доставке.

## Как проверить реализацию

- При лидере №3 инженер может выбрать №2. После переключения тестовое событие отправляет №2 один раз.
- После возврата №1 и смены лидера сообщения продолжает отправлять №2. После ручной передачи обратно следующее событие отправляет только №1.
- Попытка назначить №3 отклоняется, действующий отправитель сохраняется. Назначенные проверки на узлах продолжаются независимо от выбора отправителя.

Реальную доставку в Telegram пользователь проверяет на [шаге 3](../07-verification-and-rollout/main.md).
