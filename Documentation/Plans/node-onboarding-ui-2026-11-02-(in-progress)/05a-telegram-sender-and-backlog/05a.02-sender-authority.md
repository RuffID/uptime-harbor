# 05a.02. Authority follower и отделение от лидерства

Статус: `not-started`. Зависимости: [05a.01](05a.01-sender-assignment.md)

## Цель и результат

Независимый от роли sender authority без обхода safety gates.

Основание: [обзор этапа](main.md), [общий план](../main.md), [согласованный контракт](../technical-design.md#telegram). При расхождении краткой задачи с полным объёмом этапа требования не ослаблять; противоречие зафиксировать до зависимой работы.

## Границы и работы

- Согласованно изменить authority key/readiness/gates/runtime/lifecycle/resign/failure window и reducer/consensus, сохраняя старый variant исторических attempts.
- Привязать authority к sender/storage/assignment/epoch/coordinator term/membership/process; не использовать LeadershipToken follower как sender permit.

Затрагиваемые части: Domain delivery state/commands, Application sender/queue, Infrastructure consensus/dispatcher/results, Web status DTO и тесты.

## Проверки и критерии готовности

- Follower назначен — может получать право; неназначенный leader — нет.
- Лидер без token не resign-ится, потеря sender не рушит CanWork/consensus; обычное большинство сохраняется.

Использовать только разрешённые статические, compile-check и изолированные проверки. Приложение, БД, Docker, сеть, браузер и Telegram этим файлом не разрешаются; внешнее подтверждение относится к этапу 07.
