# 05. Подключение и восстановление

Статус: `not-started`. Зависимости: [02](02-invitations-and-contracts.md)–[04](04-enrollment-and-trust.md); К03 для назначения проверок.

## Цель

Выполнить существующий Join автоматически и проверяемо, продолжать после обрыва без дубликатов и показывать успех только после реального принятия состава и догона.

## Работы

1. Создать долговременный координатор попытки с состояниями из technical-design.md. В каждый внешний шаг входить с сохранёнными AttemptId, исходными OperationId/payload и ожидаемой версией; повтор запроса не означает новую команду.
2. Подать AdmitNode через текущую принятую авторизацию. Получить подтверждённый срез после допуска, проверить SnapshotId/digest/compatibility/minimum index/точные Nodes и Operations. Ограничить размер и потоковую передачу snapshot, защитить временные файлы и не публиковать их в wwwroot.
3. Автоматизировать локальные manifest/checkpoint и восстановление в карантине через существующие production services. Не запускать offline CLI как subprocess из Web. Падение между записью файла, проекцией и подтверждением шага должно приводить к проверяемому продолжению либо явному отказу.
4. Подать RequestMembership с исходным ID, дождаться native AddMember и принятого ConfirmMembership. Сериализация состава и проверка большинства остаются существующими. При смене прав автора/лидера выполнить предусмотренную повторную авторизацию, не создавать второй native consensus.
5. После catch-up отдельно пройти законные Activate и Enable по актуальным версиям и challenge. Ни резервирование кода, ни принятый снимок не заменяют восстановление аккаунтов, проекции и компонентов readiness.
6. Определить доказательство финального состояния: какой принятый срез достигнут, совпадает ли состав, работает ли узел и свежа ли связь. Отставание после новых команд и потерю контакта показывать отдельно. Не утверждать бесконечную синхронность по однажды достигнутому индексу.
7. Реализовать остановку до membership и поведение после него. Если voter уже принят, «Отмена» не удаляет WAL или SQL и не обещает мгновенный rollback: вернуть известный результат и предложить обычное контролируемое удаление. Не убирать действующего voter при transient timeout.
8. После принятого Join выполнить согласованный К03 шаг назначения observers отдельными общими командами; сохранить старые поколения/историю наблюдений. Ошибку назначения отличать от ошибки синхронизации.
9. Логировать переходы и результаты по одной попытке: безопасные IDs/этап/причина/индексы без payload. Не писать общий success после локального SQL commit, snapshot download или HTTP 202. При replay/resume не дублировать успешный итог.

## Затрагиваемые части

Application сценарии и независимые state-store contracts, Infrastructure state persistence/snapshot/recovery, Web Cluster runtime/lifecycle workers и безопасные status DTO. Не вводить глобальный UoW или обратные зависимости Application → Web. Обновить местные AGENTS.md, Cluster runtime, Cluster operations, Shared cluster storage и Testing.

## Проверки и приёмка

- Потеря ответа после каждого принятого шага возвращает прежний результат при retry.
- Закрытие вкладки, рестарт второго сервера, смена лидера и незавершённый snapshot не создают новый NodeId/Bootstrap/voter.
- Истёкшее/отозванное разрешение не обходится длительным Pending. Возобновление получает законное свежее основание, сохраняя ID попытки.
- Повреждённый snapshot, несовместимость, wrong membership, неверный cursor или apply fault держат рабочие gates закрытыми.
- Два параллельных membership-запроса проходят существующую сериализацию. Потеря одного из двух voters не вызывает автоматического сокращения состава.
- Отмена до/после принятия состава даёт разный достоверный результат; callbacks не включают уже отозванную/заменённую попытку.
- Telegram sender по-прежнему единственный и подтверждён существующей authority; Join не открывает отправку сам по себе.

## Результат

Пока не выполнен. Fake interleaving tests подтверждают сценарии координации, но не настоящие elections, SQL locking или fsync. Реальная приёмка обязательна отдельно.
