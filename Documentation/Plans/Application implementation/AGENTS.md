# Планы реализации UptimeHarbor

## Формат статуса

Каждый файл плана, включая `00 - Plan overview.md`, обязан сразу после заголовка содержать раздел `## Статус`.

Допустимые состояния:

- `Не начат` — реализация этапа ещё не выполнялась;
- `В работе` — выполнена только часть результата этапа;
- `Завершён` — весь результат и проверки этапа выполнены;
- `Приостановлен` — работа начата, но сознательно остановлена; рядом указывается причина.

## Правила для новых планов

- В новом плане статус определять по фактическому коду и результатам проверок, а не по намерению.
- При начале или завершении этапа нового плана одновременно обновлять его файл и статус общего нового плана.
- Если часть этапа нового плана реализована раньше очереди, отмечать этап как `В работе` и кратко перечислять незавершённое.
- Не отмечать этап нового плана завершённым при невыполненных обязательных проверках или документации.
- При изменении состава, результата или порядка этапов актуализировать этот `AGENTS.md`.

## Запечатанные исторические планы

- Существующие файлы планов `00`–`08` считать запечатанной историей реализации независимо от указанного в них статуса (`Не начат`, `В работе`, `Завершён` или `Приостановлен`).
- Не изменять их содержание, статус, шаги и отметки о проверках из-за последующих изменений проекта.
- Изменять существующий план можно только по прямой просьбе пользователя изменить именно этот план.
- Последующие доработки оформлять отдельным новым планом; фактическое текущее устройство описывать в `Documentation/Technical`.
