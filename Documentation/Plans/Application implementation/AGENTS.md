# Планы реализации UptimeHarbor

## Формат статуса

Каждый файл плана, включая `00 - Plan overview.md`, обязан сразу после заголовка содержать раздел `## Статус`.

Допустимые состояния:

- `Не начат` — реализация этапа ещё не выполнялась;
- `В работе` — выполнена только часть результата этапа;
- `Завершён` — весь результат и проверки этапа выполнены;
- `Приостановлен` — работа начата, но сознательно остановлена; рядом указывается причина.

## Правила обновления

- Статус определять по фактическому коду и результатам проверок, а не по намерению.
- При начале или завершении активного этапа одновременно обновлять его файл и статус общего активного плана.
- Если часть этапа реализована раньше очереди, отмечать этап как `В работе` и кратко перечислять незавершённое.
- Не отмечать этап завершённым при невыполненных обязательных проверках или документации.
- При изменении состава, результата или порядка этапов актуализировать этот `AGENTS.md`.

## Завершённые планы

- После присвоения статуса `Завершён` файл плана считать запечатанной историей этапа.
- Не переписывать завершённый план, его результат, шаги и заметки о проверках под последующие изменения проекта.
- Последующие доработки оформлять отдельным новым планом; фактическое текущее устройство описывать в `Documentation/Technical`.
- Исправление объективной опечатки в завершённом плане допустимо только по прямой просьбе пользователя и не должно менять исторический смысл.
