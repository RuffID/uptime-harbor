# Этап 8. Развёртывание и выпуск

## Статус

**Не начат.**

## Цель

Подготовить проверяемое односерверное развёртывание UptimeHarbor на Linux.

## Работы

1. Подготовить production Dockerfile для исполняемого проекта `UptimeHarbor.Web`, собирающий также его зависимости Domain, Application и Infrastructure:

   - multi-stage build;
   - запуск не от root, если это не мешает целевому окружению;
   - корректный порт приложения;
   - health check или совместимый `/health` endpoint.

2. Подготовить Docker Compose с сервисами:

   - `uptimeharbor`;
   - `postgres`;
   - persistent volume PostgreSQL;
   - внутренняя Docker-сеть;
   - внешний JSON-конфигурационный файл.

3. Не публиковать порт PostgreSQL наружу.
4. Подготовить пример production-конфигурации без секретов.
5. Подготовить пример Nginx reverse proxy с поддержкой:

   - HTTPS;
   - forwarded headers;
   - SignalR WebSocket upgrade;
   - разумных proxy timeout;
   - ограничения размера запроса.

6. Описать интеграцию с Certbot без автоматического управления сертификатами из приложения.
7. Описать первый запуск:

   - создание production-конфигурации;
   - запуск PostgreSQL;
   - применение миграций;
   - запуск приложения;
   - вход bootstrap-администратором;
   - немедленная смена начального пароля.

8. Проверить корректную обработку forwarded scheme и secure cookies за Nginx.
9. Проверить сохранение Identity Data Protection keys и данных PostgreSQL после перезапуска контейнера.
10. Добавить graceful shutdown фонового мониторинга.
11. Подготовить краткую инструкцию обновления версии приложения и схемы базы.

## Финальная проверка

- выполнить compile-check и полный набор изолированных тестов;
- проверить каждое условие раздела «Критерии приёмки» ТЗ;
- проверить интерфейс на настольной и мобильной ширине;
- проверить сценарии недоступного endpoint и PostgreSQL;
- проверить WebSocket через Nginx;
- убедиться, что секреты отсутствуют в image, логах и репозитории;
- убедиться, что после перезапуска данные сохраняются;
- зафиксировать известное ограничение: UptimeHarbor не может уведомить о падении собственного сервера.

## Результат этапа

Получен документированный комплект для развёртывания первой версии UptimeHarbor на одном Linux-сервере.
