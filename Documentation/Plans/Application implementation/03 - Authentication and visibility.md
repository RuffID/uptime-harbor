# Этап 3. Аутентификация и видимость

## Статус

**Завершён.** Identity, cookie-аутентификация, bootstrap администратора, управление пользователями, permissions и единая серверная фильтрация проверены сборкой и изолированными тестами.

## Цель

Реализовать безопасный вход, bootstrap начального администратора и серверную фильтрацию доступных объектов.

## Работы

1. Настроить ASP.NET Core Identity и cookie-аутентификацию.
2. Создать роли `Administrator` и `User`.
3. Реализовать идемпотентный bootstrap:

   - проверить наличие администратора;
   - при отсутствии проверить конфигурацию;
   - создать роль и пользователя;
   - сохранить пароль только в виде Identity-хеша;
   - не изменять пользователя при повторном запуске.

4. Создать страницу входа и выхода.
5. Закрыть весь интерфейс политикой обязательной аутентификации.
6. Закрыть административные страницы ролью `Administrator`.
7. Реализовать управление пользователями:

   - создание обычного пользователя;
   - установка начального пароля;
   - включение или блокировка пользователя;
   - удаление пользователя;
   - назначение разрешённых серверов и отдельных контейнеров.

8. Создать сервис вычисления доступных объектов для текущего пользователя.
9. Применить серверную фильтрацию во всех запросах чтения, включая SignalR.
10. Не разрешать назначение контейнера без его родительского сервера.

## Требования безопасности

- изменение данных выполняется только через POST с antiforgery;
- проверка роли выполняется на сервере;
- отсутствуют публичная регистрация и восстановление пароля по email;
- ошибки входа не раскрывают существование логина;
- административные DTO не передаются обычному пользователю;
- заблокированный пользователь теряет доступ после завершения или инвалидации сессии.

## Тесты

- bootstrap в пустой базе;
- повторный bootstrap не меняет пароль;
- обычный пользователь получает запрет на административный endpoint;
- пользователь видит только назначенные серверы и контейнеры;
- доступ к серверу не открывает все контейнеры автоматически;
- прямой запрос скрытого объекта возвращает запрет или отсутствие объекта;
- удаление пользователя удаляет его разрешения.

## Результат этапа

Работают вход, роли, управление пользователями и единая серверная модель видимости.
