# Документация UptimeHarbor

## Назначение и аудитория

Бизнес-требования предназначены для согласования поведения системы. Технические документы помогают разработчику и сопровождающему понять текущую реализацию. Планы и отчёты ревью фиксируют работы и доказательства в их историческом контексте.

## Бизнес-требования

[Business logic/README.md](Business%20logic/README.md) — навигация по пользовательским правилам. [Business requirements.md](Business%20logic/Business%20requirements.md) описывает назначение, роли, мониторинг, видимость, уведомления, ограничения и критерии готовности первой версии.

## Техническое устройство

[Technical documentation/README.md](Technical%20documentation/README.md) — оглавление актуальных документов об архитектуре, данных, Web, конфигурации, проверках и эксплуатации.

## Планы и история

- [Plans/README.md](Plans/README.md) — активные планы, правила оформления и навигация по запечатанному плану реализации.
- [Несколько узлов, ревизии и права на сущности](Plans/multi-node-sync-and-permissions-2026-10-18-%28not-started%29/main.md) — согласованная будущая доработка; реализация не начата.
- [Первичное техническое ревью v1](Technical%20documentation/V1%20Technical%20Review%20Findings.md).
- [Повторное техническое ревью v1](Technical%20documentation/V1%20Follow-up%20Technical%20Review.md).

Оба отчёта ревью являются историческими: оговорки в их начале объясняют последующие исправления и переход на SQL Server. Их старые списки дефектов, версии провайдера и счётчики тестов не являются текущим результатом проверки.

## Границы подтверждения

Текущее устройство определяется исходниками и тематическими документами. Результаты новой проверки библиотек приведены в [Libraries.md](Technical%20documentation/Libraries.md). Непроведённые SQL Server, HTTP runtime, browser, Telegram и deployment-проверки остаются открытыми; статические проверки и компиляция их не заменяют.
