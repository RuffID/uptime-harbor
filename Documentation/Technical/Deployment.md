# Сборка и развёртывание

## Состояние реализации

В Web-проекте есть multi-stage Dockerfile, который восстанавливает и собирает Domain, Application, Infrastructure и Web, копирует локальные DLL из `libs` и запускает `UptimeHarbor.Web.dll` на ASP.NET runtime image. Deployment-шаблоны, Nginx-конфигурация, Docker Compose и orchestration не входят в требования первой версии и в репозитории не поставляются.

## Границы первой версии

Первая версия не фиксирует целевую схему reverse proxy, контейнеров или orchestration. Выбор средств запуска Web и PostgreSQL, сетевой изоляции и хранения данных остаётся ответственностью окружения.

## Конфигурация и данные

Production-конфигурация и секреты должны задаваться средствами целевого окружения вне репозитория. PostgreSQL data и Identity Data Protection keys (таблица `data_protection_keys`) должны сохраняться средствами этого окружения.

Перед запуском новой версии схема БД обновляется отдельным шагом. Автоматическое применение миграций при старте Web отключено; подробности находятся в [Database migrations.md](Database%20migrations.md).

## Health и остановка

Web предоставляет `/health/live` для liveness и `/health/ready` для readiness с проверкой PostgreSQL; `/health` — совместимый алиас readiness. Миграции применяются отдельной ручной командой до запуска новой версии и не выполняются автоматически при старте Web.

## Выпуск и откат

Автоматизированный Compose-сценарий выпуска и отката не является частью первой версии. При необходимости оператор отдельно конфигурирует reverse proxy, Web и PostgreSQL выбранными средствами окружения, передаёт секреты вне репозитория, применяет миграции до запуска новой версии и выполняет backup/rollback по правилам своей инфраструктуры.

Runtime-проверки TLS, WebSocket, миграций, backup/restore и rollback в этой задаче не выполнялись.
