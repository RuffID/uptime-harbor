# Доменная модель

## Объекты мониторинга

`MonitoredObject` содержит общее состояние сервера и контейнера:

- неизменяемый `Guid`;
- URL endpoint и описание;
- признак включённого мониторинга;
- последнее полученное имя;
- текущий `MonitoringStatus`;
- число последовательных ошибок;
- время последней и последней успешной проверки;
- признак отправленного outage-уведомления.

`MonitoredServer` добавляет операцию успешной проверки сервера. `MonitoredContainer` хранит `ServerId` и последнее время запуска `StartedAtUtc`.

## Создание и изменение

Объекты создаются только с непустым идентификатором и абсолютным HTTP/HTTPS URL. Описание нормализуется, пустая строка превращается в `null`. Длины URL, описания и полученного имени ограничены `ModelConstraints`.

Публичных сеттеров для значимого состояния нет. Настройки меняются через `UpdateSettings` или `SetMonitoringEnabled`, результаты проверок — через специализированные методы.

Смена endpoint очищает имя и времена, полученные от предыдущего адреса, а также сбрасывает статус и инцидент. Для контейнера дополнительно очищается `StartedAtUtc`.

## Переходы мониторинга

Начальное состояние — `Unknown`.

- Успех из `Unknown` даёт `BecameAvailable` и состояние `Available`.
- Ошибка увеличивает `ConsecutiveFailures`.
- Достижение порога ошибок переводит объект в `Unavailable` и даёт `BecameUnavailable`.
- Успех из `Unavailable` даёт `Recovered`.
- Отключение мониторинга даёт `MonitoringDisabled`, возвращает `Unknown`, сбрасывает ошибки и признак уведомления.

Повторная ошибка уже недоступного объекта не создаёт новый переход. Успех всегда сбрасывает счётчик ошибок.

## Время

Доменные методы принимают `DateTimeOffset` только с нулевым смещением. Время запуска контейнера не может быть позже времени проверки.

## Уведомления и доступ

`TelegramChat` хранит внутренний идентификатор, Telegram chat ID и отображаемое имя. `NotificationBinding` через фабрики создаёт связь ровно с сервером или контейнером.

`ServerVisibilityPermission` и `ContainerVisibilityPermission` хранят идентификаторы пользователя и доступного объекта. Правило «контейнер можно назначить только вместе с родительским сервером» дополнительно закрепляется схемой БД и должно координироваться use case.

## Покрытие тестами

Тесты проверяют основные переходы, сброс ошибок, отключение мониторинга, очистку endpoint-specific состояния, UTC и допустимость notification binding.
