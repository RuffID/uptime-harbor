# Monitoring domain

## Ответственность

Каталог содержит единую сущность MonitoredServer, enum ServerType (Server / Application) и переходы между состояниями Unknown, Available и Unavailable.

## Инварианты

- Результат проверки нельзя записывать для отключённого объекта.
- Даты результатов проверки должны быть в UTC.
- Ошибка увеличивает последовательный счётчик; успех обнуляет его.
- Отключение мониторинга сбрасывает состояние инцидента без recovery-перехода.
- Смена endpoint очищает данные, полученные от прежнего endpoint.
- Endpoint обязан быть абсолютным HTTP/HTTPS URL с непустым host и укладываться в доменное ограничение длины.
- Сервер имеет обязательное нормализованное административное имя; успешная проверка меняет только отдельное внутреннее `LastKnownName`.
- Успешная проверка сервера и контейнера требует время запуска в UTC, не позже времени проверки. `StartedAtUtc` обновляется при успехе, сохраняется при ошибке и очищается при смене endpoint.
- Переход `BecameUnavailable` создаёт новый `CurrentIncidentId`; recovery сохраняет его до следующего инцидента, а ручное отключение или смена endpoint очищают.
- Только Application допускает nullable ServerId; пустой ID и ссылка на себя запрещены. Родителем может быть только Server. AssignServer сохраняет monitoring state, увеличивая Version и версии затронутых серверов. Оба типа имеют Name, отдельное LastKnownName и StartedAtUtc.
- Каждое административное изменение или записанный результат проверки увеличивает явный `Version`, используемый persistence как optimistic concurrency token.
- `ConfigRevision` и `CheckGeneration` присваиваются отдельно при применении принятой конфигурации; локальная проверка не изменяет их. Отдельные observer streams и общие инциденты находятся в `Cluster`; локальное состояние не заменяет принятую историю.

При изменении переходов, полей или порогов обновлять этот файл, доменные тесты и `Documentation/Technical documentation/Domain model.md`.
