# Локальный setup и runtime

`CredentialContinuationOrigin` задаёт доверенный browser origin работающего лидера для machine HTTPS. `CredentialContinuationPeerAddress` задаёт точный принятый Raft URL того же лидера для подписи. Startup закрепляет оба адреса на исходный boot и проверяет voter и issuer по локальному replay.

`DynamicPeerTls` публикует первый снимок ContinueCredential под startup Transition по типизированному срезу с исходным Bind и регистрацией текущего boot. Снимок проверяет boot, профиль, recovery и свежесть. Допуск TLS/peer и рабочая публикация требуют последующей отдельной проверки под native replay.

Renewal/ владеет voter intent/key/authorization/DER pins, durable Bind reconciliation, установкой и публикацией CredentialRevision в managed Direct. Штатный сценарий renewal сериализуется через InstallationState.VoterRenewal, внутри сохраняется обычный порядок захвата Transition. ManagedRestart проверяет replayed Bind для native Raft и завершает установку на свежем majority. Рабочая ротация допускается через отдельный typed вход managed Bootstrap Direct. Записи остаются вне общего snapshot и SQL. Подробности в Renewal/AGENTS.md.

Worker ротации использует RestartableWorker и отдельный scope на каждый проход. Supervisor запускает его в рабочей группе Bootstrap Direct. После нового Bind готовность, Process и Enable используют действующую опубликованную CredentialRevision.

Dedicated `DynamicPeerTls` проверяет credential из envelope и предъявленный leaf на одном accepted срезе. Публикация CredentialRevision меняет одним снимком локальные leaf/ID и ключ выбора HTTP handler. Прежние захваченные снимки действуют в рамках accepted overlap; ошибка публикации, откат среза или смена recovery epoch блокируют их до свежей публикации из проверенного материала. Не сбрасывать отказ через базовый Install/Probe или менять профиль в обход Transition.

Снимок ContinueCredential до handoff доступен для native Raft и подписи точного ProcessRenewal установленным ключом. Сверять текущую accepted lease и Bind. Для снятия транспортного карантина нужен новый атомарный снимок со свежим доказательством принятого Process. OnlineEnableState по-прежнему требует штатное принятое потребление Enable и рабочий TLS-снимок.

Signing repositories/journal/locks и ленивый EnrollmentIssuerStorage регистрируются также для Legacy. Manual issuer требует явно настроенных отдельных persistent StateDirectory/SecretDirectory/KeyDirectory; ключи setup не сканировать как пустое manual хранилище. Регистрация browser use case остаётся в AddWebPresentation, новые default paths или профиль установки не создаются.

InstallationIntent=Setup обрабатывается до legacy initialization. Межпроцессный installation/storage lock удерживается весь срок процесса; порядок блокировок transition → runtime lifecycle → membership → write gate. Секреты и профиль не реплицируются. SQL-транзакции не охватывают файловые и сетевые операции.

AES-GCM использует отдельный persistent wrapping-key volume, без DPAPI. Не восстанавливать пароль из изменённого config, не активировать orphan key files. Любая неизвестная evidence оставляет common/peer/delivery gates закрытыми. Логи содержат только ID, фазу, revision/generation и закрытый reason code после durable результата.

ValidateProgressAsync проверяет всю историю LocalStepRecord страницами по 256 без tracking, с keyset по первичному Id. Сортировку и сравнение cursor выполнять одним SQL provider; не заменять их порядком Guid в памяти, OFFSET или общим пределом истории. Не фильтровать страницы по AttemptId: чужая запись должна приводить к отказу. Проверка выполняется при startup под installation/storage lock до запуска runtime writers; прежние command identity/digest/revision проверки сохранять для каждой страницы.

Purpose issuer использует epoch в AES AAD. Startup загружает exact install/cluster/generation/node/storage issuer refs перед ReconcileAll; foreign/duplicate/orphan refs закрывают запуск. Новый BootChallenge создаётся InstallationLease на каждый процесс и не восстанавливается из профиля. Accepted process resume и ManagedRestart не заменять локальной lease. ManagedStorageSeals связывает AEAD checkpoint с profile/manifest/snapshot/SQL; restart запускает только целый прежний storage в quarantine до majority, затем требует новый ProcessEpoch/Enable. Отсутствующий/усечённый WAL и offline markers не разрешают catch-up fallback.

ManagedWalValidation читает исходные state/checkpoint под installation lock до создания WAL: DotNext может обнулить короткий state и поднять индексы до snapshot. Проверка привязана к формату DotNext 6.10.0 (state vote/member/term, checkpoint v1); при обновлении пакета сверять формат и изолированные restart tests. Term и committed index не ниже SQL head, last не ниже committed; неподтверждённый commit после сбоя требует offline recovery, snapshot не заменяет эту evidence. Seal не понижает index/term и не меняет term/head digest на том же index; повтор точного cut допустим.

Ротация при ManagedRestart сохраняет исходные profile/seal и выбирает credential по проверенному WAL replay. Если защищённый slot заканчивается на Bind intent, для native Raft используется точный прежний credential. Исходный Bind сверяется после свежего majority; только подтверждённый результат разрешает установку. Process и Enable используют leaf рабочего снимка. Общий доступ закрыт, если рабочий снимок отсутствует или перестал совпадать с accepted state.

Protected invitation — inline AES envelope в локальной attempt; после доказанного accepted reserve удаляется до issue. JoinEnrollmentAuthority сохраняет прежние key/CSR/request/IDs/DER и reconciles lost response через fresh read-state. EnrollmentTrustInstallation сохраняет SQL intent перед protected manifest, не активирует orphan/partial refs. EnrollmentProbeSession выдаёт certificate/allowlist ≤2 минут только для фиксированной peer-пробы до runtime; ordinary peer/Raft/common gates не открывать. Public BotId первого берётся из ExpectedBotId либо bounded getMe, Join получает его из descriptor без token. DNS проверять на каждом connect с IP pinning/SNI, redirects/cookies/proxy запрещены.

Read-state/resume/process-renew в CertificateAuthorized до Bind могут не содержать public DER на сервере: после проверки неизменного issuance клиент сохраняет descriptor, возвращённый EnrollmentDescriptorValidation.Bound с прежними DER. Последующие ответы не должны менять эти байты. Успех E4 публиковать только после обеих peer-проб; сохранённый trust intent или accepted nonvoter после отказа пробы не означают завершение E4.

Setup production Bootstrap проходит точные GenesisAuthorization/permit/account и отдельные accepted process/activation/enable; setup identity не становится common user. ManagedRestartPreparation отвергает любой Cluster.Mode, кроме точного Restart, до чтения storage, публикации admission и установки TLS. ManagedRestart пока связан с новым первым; полноценный Join/snapshot/membership — 05, sender — 05а. Не объявлять E4 общим Ready и не обходить закрытые production gates незавершённых сценариев 04.
